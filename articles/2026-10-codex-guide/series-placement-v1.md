# 六篇系列：文件、上下文与自动执行机制的归属

日期：2026-10-07。承接 series-outline-v3.md，并按本轮要求补充。原系列顺序保留；第二篇不再采用具体项目贯穿全文，也不恢复七维清单。

## 六篇各自负责的问题

1. 认识系统：入口、工作环境、模式与能力关系。
2. 共同判断：需求与方法不完整时如何探索、评估、执行、验证，形成有效做法。
3. 保存与接续：项目、文件、版本和规则怎样组织；稳定方法怎样成为技能。
4. 实际推进：工具执行、上下文分工、审阅与检查怎样运行。
5. 对外交付：发布、部署、服务、访问与真实用户使用。
6. 长期改进：维护、自动化、工作流评估与持续复用。

## 避免重复的规则

第二篇讲为何需要与协作关系，保留一张文件职责表。第三篇给可修改的文件例子、目录与读写安排。第四篇讲运行这些机制时的动作、分工与检查。第六篇讲长期自动化是否值得及怎样维护，不重新教每个文件名称。

以具体问题组织，文件与工具作为解决方法出现。不能把第三篇写成全部术语与配置的百科；跨产品对照只解释相关差异，不展开完整 Claude Code 入门教程。

## 事实与编辑边界

AGENTS.md 及 CLAUDE.md 的加载分别按官方产品文档说明。GOALS.md、PROMPTS.md、build-log.md 等是引用的 OpenAI 工作流示例约定，非产品强制文件。PLANS.md 的组织方式也可调整，文件与计划模式不同。

独立上下文不天然等于独立事实来源，钩子触发不保证检查通过。第三、四、六篇正式写作时重新核对当时功能与配置，不凭本表断言跨产品兼容。

用户明确第四篇需解释 Codex 背后的工作方式，并帮助读者减少提醒与返工、更好地获得交付物。当前候选见 part-4/outline-v2.md，按信息进入、任务判断、工具执行、交付形成、长任务接续、反馈修正组织。不是单纯的开发步骤或游戏故障处理教程，也不只讲“有能力却没主动采用”的缺口。
