# AI 交付物全景图鉴

标题候选｜AI 交付物全景图鉴

你已经让 AI 写文章、做图片，说不定连自己的网页都做过一个了。下一次，还想试点什么？

一个装在手机里的小应用，一个收到表格就返回处理结果的机器人，一个能转到背面看的收纳架模型，一套换了名单就能重新生成证书的程序——随便挑一个，都能成为下一件作品。

很多东西以前没想到，多半是没见过它怎么做出来的。认识的成品多了，能下手的地方就多了。这份图鉴按使用和制作方向分成十组，你可以从熟悉的地方读起，也可以直接跳到最感兴趣的一组。

每组表格留三列：可以拿到什么，具体在哪里用，以及一句可以直接向 AI 提出的要求。左边先认名字，中间看软件、平台和实际文件，右边找一个可以开始的小任务。一行里的不同作品例子不必全部制作，先挑一个就好。

表中的软件是一条具体路线，帮助你看懂成果长什么样。已有 Excel、Figma、Blender 等使用偏好，可以直接点名；不知道用什么工具，就先说想做的东西和使用动作，让 AI 调查适合的方法。交办时还可以统一补一句：

> 请先研究适合的方法，做一个简单可用的版本，说明拿到什么、怎样打开或运行，需要哪些软件、账号、模型或接口。

这些作品是说明性设计示例，能否制作取决于实际可用的工具、平台、账号与设备条件。**做的时候用了 AI，不代表用起来离不开 AI。** 图片和视频生成后可以直接播放，清单、计算器和批处理程序也可以按规则运行；需要模型现场判断的任务，再安排模型连接。

## 一、能直接打开或进入的应用

网页、App、小程序、游戏，都是可以真正打开和操作的成果。网页里还能放一个预算计算器、一张能筛选的销售看板，或者一套库存管理工具。从这些具体作品里，可以找到一个想试的方向。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 网站与网页应用 | 在浏览器打开并操作的完整网页，例如作品集、比较报告、计算器、数据看板或库存管理。交 HTML、CSS、JavaScript、数据和素材；需要后台时另附服务工程。交互地图、三维展示、搜索知识站和在线问卷也是可选作品例子。 | 做一个 HTML 产品比较网页，交 HTML、CSS、JavaScript、数据和素材；能筛选并查看来源，附启动方法。 |
| 手机和平板 App | 装进手机或平板使用，例如能勾选保存的出行清单。iPhone/iPad 可交 Swift/Xcode 工程，Android 可交 Kotlin/Gradle 工程与约定的测试版本，符合条件时附 APK；说明目标系统与安装方法。 | 做一个 iPhone 出行清单 App，交 Xcode 工程、测试方法和安装说明，勾选状态能保存。 |
| 电脑应用 | 在 Windows/macOS 打开使用，例如能预览再改名的图片整理工具。可以采用 Electron 等路线，交完整工程、素材和目标系统的运行版或安装包；窗口、菜单栏、托盘是入口选择。 | 做一个Windows图片整理工具，能预览再执行改名；先研究合适实现，交完整工程和可运行测试版。 |
| 平台小程序 | 在微信等指定平台内使用，例如预约、活动报名或报修。微信版交开发者工具能打开的 WXML/WXSS/JavaScript 工程、配置及必要后台；飞书、小红书等平台要交各自对应工程并核对条件。 | 做一个微信预约小程序，交微信开发者工具能打开的工程、测试入口和后台配置说明。 |
| 游戏与互动故事 | 能实际点击、游玩并重新开始，例如小型解谜或分支故事。可交 Godot 工程（project.godot、场景、脚本、素材）与运行版，或采用 HTML/JavaScript 路线；平台内小游戏另核对目标支持。 | 做一个点击解谜小游戏，先选合适引擎，交能玩的测试版、完整工程和素材，说明以后怎样修改。 |
| 虚拟空间体验 | 在约定的头显或兼容设备中进入、观察和操作，例如虚拟展厅。可以交 Unity 等引擎的完整工程、场景素材、SDK说明与目标设备测试版。 | 为约定头显做一个虚拟展厅，先核对设备、引擎与SDK，交完整工程、可运行小样和启动方法。 |

可以试做一份自己的出行打包清单：新建“周末露营”，加入帐篷、头灯和雨衣；装进包里的点一下勾选，下次出行复制清单接着用。做成 HTML 网页，就从浏览器进入；做成 App，就从手机图标打开；做成微信小程序，就在微信里操作。第一次选一种入口就够。

保存到本机和跨设备同步是两种设计，普通的勾选功能可以按规则运行。网页和小程序则需要分别适配，微信官方也提供了独立的[小程序示例工程](https://github.com/wechat-miniprogram/miniprogram-demo)。一个能在浏览器打开的文件，不会自动变成已经安装好的手机应用。

制作与运行条件：网页需要 HTML/CSS/JavaScript 或相应框架，手机和桌面应用要匹配的开发、构建与安装环境。交付时说清可编辑工程、测试版本和实际使用入口；多人记录、同步或实时数据再安排后台与连接。虚拟空间还需兼容设备与 SDK。

## 二、装进现有软件里的扩展

有些小作品适合长在常用软件里：阅读网页时多一个摘录按钮，Excel 里多一条检查命令，Blender 里多一个批量导出工具。入口就在原来的工作环境中。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 浏览器插件 | 装进 Chrome/Edge 等约定浏览器后使用，例如选中文字保存摘录。交 manifest.json、脚本、弹窗 HTML、图标和加载说明。 | 做一个 Chrome 摘录扩展，交 manifest.json 和完整工程，保存选中文字、网址和备注，附加载方法。 |
| 办公软件插件 | 在现有办公文件里直接操作，例如 Excel 原表重复项检查。宏路线交支持的桌面 Excel 可打开的 .xlsm 与 VBA 源码；Office 网页插件则交对应工程和清单，注明兼容条件。 | 给桌面 Excel 做重复项检查宏，交 .xlsm、VBA 源码和样例，写清适用平台与版本。 |
| 代码编辑器插件 | 在 VS Code 安装后执行命令，例如检查失效链接并跳到位置。交扩展工程、package.json、源码、构建出的 .vsix 与测试样例。 | 做一个 VS Code 链接检查扩展，交工程、.vsix 和测试样例，能跳到失效链接位置。 |
| 设计软件插件 | 在 Blender 等指定制作软件中执行批量操作，例如批量命名和导出模型。Blender 路线交 Python 插件包、脚本、.blend 样例及版本说明；其他设计软件按其宿主交付。 | 做一个 Blender 批量导出插件，交可安装包、Python 源码和 .blend 样例，说明兼容版本。 |
| 网站系统插件 | 装进已有 WordPress 等网站系统，例如给站点增加活动报名。WordPress 路线交 PHP 插件目录、可安装 ZIP、管理界面、配置和测试说明。 | 给 WordPress 做活动报名插件，交可安装 ZIP、源码和测试方法，说明适用版本。 |
| 桌面小组件与系统扩展 | 从设备桌面卡片或系统入口使用，例如 iPhone 日程小组件、电脑文件右键动作。iPhone 可交 WidgetKit/Xcode 扩展工程；Windows/macOS 按目标系统的扩展机制交付。 | 做一个 iPhone 日程小组件，交 WidgetKit/Xcode 工程，说明系统要求和测试方法。 |
| 游戏扩展包 | 导入已有游戏而不是另开一个独立游戏，例如可安装关卡或规则包。Minecraft Java版可交约定版本的数据包（pack.mcmeta、函数与资源）；其他游戏按对应编辑器和加载规则交付。 | 为指定版本的 Minecraft Java 版做规则数据包，交完整目录、安装方法和测试记录。 |

设想读文章时选中一段文字，点一下按钮，摘录、网址和备注就存好了。可以先做一个只在指定网页生效的 Chrome 扩展，用顺手了再增加导出或同步。想要自动摘要，再安排模型连接。Chrome 官方[入门教程](https://developer.chrome.com/docs/extensions/get-started/tutorial/scripts-on-every-tab)中的阅读时间扩展，就展示了这样一个范围很小、但可以独立使用的成果。

拿到后，要能在约定浏览器里加载，选中文字、保存记录、导出再检查。“插件”必须说明装进哪里：Excel 宏、VS Code 扩展和 Blender 插件使用的接口与加载方法各不相同。

制作与运行条件：写清宿主软件、版本、权限、安装包或加载目录，并附一次可核对的使用样例。普通摘录和规则处理不一定需要模型。游戏扩展也要对应具体游戏与版本，不能只交一个不知安装到哪里的压缩包。

## 三、能重复执行、接入或复用的程序工程

一次任务做完，还可以把以后继续处理的办法留下来。换一批文件、换一份名单，程序再跑一次；或者让另一个应用来调用同一套处理逻辑。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 批处理程序 | 换一批文件或数据还能再次运行，例如照片整理、数据清洗、证书生成、质量检查、网页自动录入或按数据生成动画。Python路线交 .py、依赖、输入样例和模板；Node.js路线交相应工程和启动方法。 | 做一个读取名单生成证书的程序，换名单后还能再跑，交代码、依赖、CSV样例、模板和启动方法。 |
| 自动化工作流与快捷指令 | 导入兼容平台并配置后执行，例如定时报告、新文件校验、订单同步、构建测试，或按条件联动灯具。n8n路线交工作流JSON与连接说明；苹果快捷指令、家居平台流程按各自格式和设备条件交付。 | 把取数、清洗和生成报告做成 n8n 工作流，交可导入 JSON、节点依赖与连接说明。 |
| 接口服务（API） | 供网页、App或其他程序提交数据并取得结果，例如运费计算、库存查询、表格转换、预约登记、文本分类或订单事件接收。FastAPI路线交Python服务工程、依赖、启动方法和调用样例；是否接模型由用途决定。 | 做一个能让网页调用的运费计算服务，按重量和目的地返回明细，附代码、启动方法和调用例子。 |
| 可复用代码包 | 给别的程序拿来使用的一包代码。例如 Python 校验规则包，交源码、安装说明和使用样例；若是连接某项服务的 SDK，还要说明它依赖哪项服务。 | 把这些校验规则做成 Python 软件包，交源码、pyproject.toml、安装与调用样例。 |
| 可嵌入的界面组件 | 能装进网页项目的一块真实界面，例如 React 预约日历。交 TypeScript 代码、样式、演示页面和接入说明；开发者把它接进自己的程序。 | 做一个 React 预约日历组件，交 TypeScript 源码、样式、演示和输入输出说明。 |

证书生成器是很直观的小尝试：定好版式，把姓名、活动名和日期设成替换字段，再读一份虚构名单，为每个人生成 PDF。换一份名单，重跑一次，下一批就出来了。试用时可以专门放进一个很长的名字，看看文字会不会溢出、有没有漏文件。

这次生成的 PDF、可修改的模板、下次还能运行的程序，要一起说清楚。想让它定时启动，或收到新文件就执行，再配触发机制和执行环境。n8n 的[工作流导入导出](https://docs.n8n.io/workflows/export-import/)解决的是流程定义的保存与转移，实际执行还需要平台和连接配置。

接口服务则把使用动作交给另一个程序：网页传入重量和目的地，服务返回运费明细。查询、计算、转换都可以采用这种交付方式。像 [FastAPI 的示例](https://fastapi.tiangolo.com/tutorial/first-steps/)那样，服务工程、启动方法和调用入口要能对应起来。

制作与运行条件：处理程序附依赖、样例和启动方法；工作流附兼容平台与连接说明；接口服务交代运行位置、参数、结果和错误反馈。代码包与界面组件还要有集成示例。定时、事件触发和跨系统同步是项目条件，按实际需要配置。

## 四、助手、聊天机器人与 AI 能力包

“助手”“Agent”“机器人”下面，可能是平台里的配置，也可能是自己电脑或服务器上的程序。先看入口在哪里、实际交什么，再理解它怎样接任务。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 平台里的专用助手 | 例如在 Dify 里配置的课程答疑助手，在该平台打开并提问。交助手配置、资料与连接说明；其中 DSL 是可导入的配置文件，不代表资料和模型账号也一起迁移。 | 在 Dify 做课程答疑助手，使用这些资料，交可复用配置、资料清单和模型设置说明。 |
| 能继续接任务的助手（Agent） | 例如自己电脑上的 Python 研究助手：输入新问题，它能检索、补查并保存结果。交运行程序、工具连接、依赖、配置样例和打开方法；若有网页入口，说明页面和执行程序各在哪里。研究之外，也可面向编程修复、数据分析、工单处理或浏览器/桌面操作；模型、工具和权限按任务另配。 | 做一个在我电脑上运行的研究助手，能接新问题并补查来源，交程序、打开方法和模型连接说明。 |
| 聊天机器人 | 例如飞书里的订单表检查机器人：人在飞书发文件，程序处理后回传结果。交飞书应用配置、Python/Node.js 服务端代码、权限与部署说明。微信版要写明公众号等具体入口；自己的网页/App聊天应用放第一组，不在这里再算一项。通知推送、订单查询、资料问答和报修登记也是平台机器人的用途例子，按平台接口能力实现。 | 做一个飞书机器人，我发订单表，它检查后返回文件，交运行代码、平台配置和启动说明。 |
| AI 技能包（Skill） | 让兼容的 AI 助手以后能重复使用的一套做事方法。例如报告制作技能包，包含任务说明，可附脚本、模板和样例。交完整文件包，并说明装进哪个助手、怎样调用。SKILL.md 只是包内那份说明文件的名字。 | 把这套报告做法整理成可复用的 AI 技能包，带模板和需要的脚本，说明给哪个助手用、怎么安装和调用。 |
| 给 AI 接工具的服务（MCP） | 例如让兼容的 AI 应用调用库存查询程序。交 Python/TypeScript 工具服务、启动方法与客户端连接样例；MCP 是连接协议，库存查询等业务能力仍要有实际程序和数据。 | 让兼容的 AI 应用能查这份库存，做成 MCP 工具服务，交代码、启动和连接方法。 |
| 经过专门调整的模型 | 例如针对某项分类任务调整的模型，或需要配合原模型加载的一组适配文件。交适配权重、原模型名称、加载脚本与评估结果；LoRA 是可能采用的适配方法之一。 | 先判断这些样本是否值得微调；合适时交调整成果、原模型信息、加载方法和效果检查。 |

飞书附件检查机器人的使用过程可以很简单：在飞书会话发来一张订单表，服务程序取得文件、检查字段、列出重复或缺失记录，再把结果文件发回来。飞书官方的[机器人教程](https://open.larkoffice.com/document/develop-an-echo-bot/introduction)展示了消息入口与运行代码怎样配合。入口在飞书，处理程序仍需要在本机或服务器执行。

规则固定时，这条流程可以不接模型。若希望助手接到研究问题后自行检索材料，发现关键数字没出处再补查，就需要模型参与选择下一步，程序负责调用工具、取回反馈并保存状态。本文用“任务 Agent”指这种能围绕目标继续推进的系统；[Agent 与工作流的区分](https://www.anthropic.com/research/building-effective-agents)也有助于理解两种执行方式。

平台中的专用助手、AI 技能包和 MCP 工具可以为同一件产品服务。技能包保存一类任务的说明，可附脚本和模板；SKILL.md 是其中说明文件的名字。MCP 让兼容应用连接工具；模型适配则涉及模型本身的调整，和把资料交给模型检索使用是不同做法。

制作与运行条件：先确定平台与入口、程序在哪里执行、模型从哪里来、工具能读改什么。消息机器人要平台接口与权限，任务 Agent 要模型和执行环境；Skill 与 MCP 要兼容宿主。Dify 的[导出配置](https://docs.dify.ai/en/cloud/use-dify/workspace/app-management)也不代表资料内容和账号一并迁移。微信需明确具体消息入口；小红书私信等能力要另查开放条件，不从小程序入口推定能接。

## 五、能导入、查询或重新计算的数据与资料

整理好的资料、能查询的数据、改输入就会重算的表格，本身就是可以接着用的成果。它们也能直接进入已经熟悉的软件，不必都先做成一个新应用。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 整理好的资料库 | 按主题找到原文、出处和相关材料，例如读书资料库。交分主题PDF/Markdown文件夹、来源表和索引，在文件管理器或Markdown工具中查阅；配更新说明。 | 整理这些资料，交分主题目录、原文、sources.csv 和 Markdown 索引，保留来源。 |
| 整理好的数据 | 导入Excel、数据库或分析程序继续使用，例如产品记录、标注与评估样本、结构化题库。可交CSV/JSON、字段单位、来源、标注规则和异常行说明，按实际数据选择格式。 | 清洗产品记录，交 UTF-8 CSV、字段和单位说明、来源及异常行清单。 |
| 可查询的数据库 | 用条件查找产品、评价和来源等关联记录。SQLite路线交 .sqlite 数据库、建表SQL、导入方法和查询示例，在SQLite工具或程序中使用。 | 把产品、评价和来源做成 SQLite 数据库，交数据库文件、建表 SQL 和常用查询。 |
| 带公式的表格 | 在Excel等兼容软件里改输入、看重算结果，例如预算、排班或成本测算。交 .xlsx，保留输入、公式和图表，不交成图片表格。 | 做预算 Excel，交 .xlsx，人数和场地费可改，公式与图表保留并标清输入。 |
| 可重跑的分析笔记本 | 在Jupyter中逐步运行、查看分析过程并换数据重算。交 .ipynb、数据目录、Python依赖和结果，附从头运行的方法。 | 把分析交成 Jupyter .ipynb，附数据、Python 依赖和从头运行的方法。 |
| 可导入日历等软件的记录 | 把整理结果放进原来使用的软件，例如课程表导入日历、联系人导入通讯录、书目导入文献工具。按目标交 .ics、.vcf 或 .bib 等文件并验证，不要求每种格式都交。 | 把课程表交成可导入日历的 .ics，明确时区和重复规则，附验证样例。 |

想亲手调假设，可以试一个预算 Excel：改人数、改场地费，看总支出怎么变。输入格、公式和结果保留在工作簿里，后续使用时仍可以继续检查和修改。如果想逐步看清分析怎么算出来，就留下 Jupyter [计算笔记本](https://jupyter-notebook.readthedocs.io/en/stable/notebook.html)，换数据后再从头运行。

日程还能再进一步：把课程表做成 .ics 文件导入日历，在原来每天使用的日历里查看，实际检查日期、时区和重复项。成果不一定只是一张供人阅读的表，也可以是别的软件直接接收的记录。

制作与运行条件：数据和资料保留字段、单位与来源；工作簿在兼容软件里核对重算；笔记本附内核、依赖和数据入口；导入文件说明目标工具与检查方法。语义检索和资料问答若要继续做成系统，再配检索、模型与使用入口。

可以做一套植物识别卡，正面放图，背面放名称和说明。打印后裁成卡片，看看字号是否清楚，正反面有没有对齐，裁切线是否影响使用。源文件留下，下次增加植物时就能接着改。

系列文章也可以做成 EPUB：打开目录跳到某章，调大字号，在阅读器里继续读。固定版式 PDF、可重排电子书、可填写文件和可编辑演示稿，拿到之后的使用动作不同。演示稿里需要继续改的文字和图表，要保留成对象；表单则要真的能填写和保存。

一张图片可以直接使用，设计稿可以留下图层和对象，界面原型可以让人先点一遍流程。想继续改文字、颜色、路径还是页面跳转，会影响应该拿到哪一种成果。

同样是继续修改，拿到 PSD 可以改海报文字和图层，拿到 SVG 可以改图标路径与颜色。Figma 的[设计文件](https://help.figma.com/hc/en-us/articles/15297425105303-Explore-design-files)还可以保留原型与组件；本地副本则按实际权限[导出](https://help.figma.com/hc/en-us/articles/8403626871063-Save-a-local-copy-of-files)。Figma 的按钮组件供设计使用，React 的按钮组件供程序集成，交付位置要说清。

制作与运行条件：先明确要成图、可编辑路径、分层稿还是原型，并核对实际软件支持。字体、素材和必要权限随稿说明；原生工程要在相应工具中制作、导出和检查，不能把预览图片改个后缀就当源文件。

## 八、声音、视频与动画制作材料

声音和影像既可以交成能播放的文件，也可以留下一套以后继续剪、继续调的工程。配音、播客、音乐、环境声和动画，都可以从一段小作品开始。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 声音文件 | 在播放器试听或导入剪辑软件，例如配音、播客、音乐、环境声和音效。交约定格式的WAV/MP3，写清时长，循环作品检查首尾衔接。 | 为小游戏做循环配乐，交 WAV 和试听版，检查首尾衔接，先确认制作工具。 |
| 可编辑的声音工程 | 在REAPER等约定音频软件里分别调整旁白、音乐和环境声。REAPER路线交 .rpp、完整素材和分轨WAV；需要改音符时另交MIDI .mid 与音源说明。 | 做雨天散步声音作品，交 REAPER .rpp、旁白/雨声/音乐分轨 WAV 和完整素材。 |
| 视频成片 | 用播放器观看或按平台要求发布，例如操作演示、短片、录屏剪辑。交MP4、必要封面与SRT字幕，说明画幅、分辨率和字幕方式。 | 剪一段竖屏演示视频，交 MP4 和 SRT 字幕，说明分辨率与是否另有烧录字幕版。 |
| 可继续剪辑的视频工程 | 在Premiere Pro等约定剪辑软件里换镜头、调字幕、重新导出。Premiere路线交 .prproj、完整素材和依赖说明；DaVinci Resolve等路线按其工程形式交接。 | 交可继续剪辑的 Premiere Pro .prproj，素材一并整理，附打开和重新链接说明。 |

“雨天散步”的声音作品，可以把旁白、雨声和音乐分轨保留。雨声太大，只调低这一轨；想换旁白，替换那一段，再导出播放文件。交一份 REAPER 工程和完整素材，后续才能继续这样修改。

视频同理：成片拿来播放，剪辑工程拿来换镜头和字幕，素材位置及插件条件需要一起交接。MIDI 记录的是音符和演奏事件，听起来怎样还取决于音源，和录好的声音文件有不同的用法；可参考 [MIDI 官方说明](https://midi.org/about-midi-part-1overview)。

制作与运行条件：先确认可用的录音、合成、剪辑或动画工具，交代实际采用的软件与版本。工程附完整素材和依赖，播放版检查时长、画幅和衔接。程序化动画还要保留生成程序；普通成品播放不需要重新调用制作阶段的模型。

## 九、三维、工程与空间分析项目

从一个熟悉的小物件开始，三维能让你转动观察、摆放和修改空间里的东西。想进一步明确尺寸、配合或生产条件，就会接触 CAD、切片、电路和仿真等更具体的工程。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 三维模型 | 例如 Blender .blend 源文件、GLB 交换模型和贴图目录。模型、材质或贴图及使用说明；在查看器、制作工具或游戏项目中打开和导入。例：收纳架、角色、道具。 | 做收纳架三维模型，交模型与材质，说明能在哪些工具打开。 |
| 三维场景与动画 | 例如含场景、相机、绑定或动画的 .blend 及 textures/ 素材目录。可继续编辑的场景、对象关系、灯光、相机或绑定动作；例：会场场景、角色动画。 | 做会场三维场景，桌椅和相机可调整，保留完整源工程。 |
| 可改参数的设计模型 | 例如 FreeCAD .FCStd 约束零件/装配，或保留节点与参数的 Blender .blend，按设计目的选择。保留参数、约束或生成逻辑；例：参数化书架、CAD 零件与装配。参数生成能力不自动表示适合制造。 | 做有尺寸约束的支架工程，改孔距后能重算，附编辑与检查方法。 |
| 三维打印文件 | 例如打印模型 .stl/.3mf、按目标切片器保存的工程与设置说明。目标设备对应的模型、切片工程或经说明的打印资料；明确准备和验证到哪一步。 | 为收纳件准备打印资料，核对设备、尺寸、材料和切片，说明验证状态。 |
| 切割与加工资料 | 例如 FreeCAD 等软件的 CAD/CAM 工程、按任务导出的 DXF 图纸和经说明的设备刀路资料。图纸、CAM 工程及约定设备适用的加工资料；例：板材切割、零件加工准备。 | 按指定设备研究板材切割方案，交图纸、加工工程和检查说明。 |
| 电路与电路板设计 | 在KiCad中打开和修改。例如 .kicad_pro、.kicad_sch、.kicad_pcb、所需库和物料清单。原理图、板图、元件资料和检查结果；在电子设计软件中修改、检查和导出。 | 做指定功能的电路与 PCB 工程，附物料清单、依赖元件和检查结果。 |
| 可编辑的地图工程 | 在QGIS中打开和分析。例如 .qgz 工程、GeoPackage .gpkg 数据与坐标说明。空间数据、图层、坐标和分析设置；编辑地图、重跑空间分析。例：点位、路线、区域分析。 | 把这些地点和空间数据做成 GIS 工程，交图层、坐标及分析方法。 |
| 仿真与计算工程 | 例如 Python/SciPy 计算程序、参数配置、输入 CSV、依赖与结果；特定仿真器则交其原生工程。模型、假设、参数、输入与运行方法；改条件重跑并比较。例：运动仿真、实验分析、符号与数值计算。机器人障碍物仿真、实验分析和符号计算也可作为具体任务，交相应模型与运行方法。 | 按这些条件建一个可重跑的仿真工程，保留模型、参数、结果与验证范围。 |

可以先试做一个桌面收纳架：上层放笔，下层有小抽屉，侧面留个耳机位。转到侧面看深度，再转到背面看开口，就算暂时不做实物，也能用立体对象思考设计。

接着想把上层加高，要确认修改发生在哪里：浏览器展示页可能只支持旋转，真正改结构要回 Blender 或 CAD 源工程；想输入尺寸后重新生成，则要保留参数或生成逻辑。交换出去的模型文件不一定保留制作历史，查看和编辑可以使用不同软件。

需要约束孔距、板厚和零件配合时，可以研究 [FreeCAD 的参数化设计](https://www.freecad.org/features.php)。继续打印或加工，要让材料、切片或刀路对应具体设备。地图工程和仿真也要留下数据、坐标、假设和重跑方法，一段好看的动画不能代替分析证据。

制作与运行条件：写清制作软件、源工程、交换文件和查看工具。CAD 与制造资料保留单位、尺寸依据、材料和设备；KiCad、QGIS 或仿真项目附相应库、数据与配置。设计、切片准备、仿真和实机验证分别记录到哪一步。

## 十、设备与机器人上的软件

想碰实体设备时，先说清软件要交到哪一步：烧录进板卡的固件、电脑连接设备的通信程序，还是机器人运行环境中的一个模块。软件文件、硬件设备与整机制造分别约定。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 设备固件 | 例如烧录进 ESP32 板卡、读取温度传感器的程序。交 Arduino/ESP32 工程、板卡与库版本、接线图和烧录步骤；烧录后由板卡执行。 | 为指定 ESP32 板卡做传感器固件，交工程、库依赖、接线图和烧录验证方法。 |
| 设备连接程序 | 例如电脑通过串口读取某台设备，并保存为 CSV 的 Python 程序。交付通信代码、协议、端口设置、依赖和读数样例；系统级驱动是另一种开发要求，需要另说明。 | 按指定设备串口协议做 Python 通信程序，交依赖、端口配置、读数样例和 CSV 输出。 |
| 机器人程序模块 | 例如 ROS 2 环境里的传感器节点，负责读取并发布数据。交节点代码、消息说明、依赖与启动配置，在指定版本的 ROS 2 中构建和运行。 | 做 ROS 2 传感器节点，交完整包、消息定义、launch 配置与测试记录，写清 ROS 2 版本。 |

一个读取温度并显示状态的小装置，可以从板卡、传感器、接线和通信方式开始，再做程序。拿到 ESP32 工程后，需要在对应环境构建、烧录，并检查实际读数；没有设备时，也可以先用模拟输入，但要说明验证停在哪里。

机器人里的通信程序、传感器节点和运动模块也能分别交付。[ROS 2 的节点教程](https://docs.ros.org/en/rolling/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Publisher-And-Subscriber.html)就是从小模块理解消息交互的入口。一个节点能发布数据，不代表整机已经能导航或抓取；仿真能运行，实机还需要对应检查。

制作与运行条件：指定硬件、工具链、驱动、协议与兼容元件；附接线、端口、依赖和启动配置。基础采集、通信与固定控制不默认需要大模型。交付对象与实际验证结果要对应，软件文件不替代硬件本身。

## 从清单里选一件真正想试的东西

留意自己在哪一行停了下来：是手机里的小应用，飞书里的机器人，能改尺寸的模型，还是属于自己的声音工程？第一步可以先描述想拿到的东西和使用动作，让 AI 调查适合的方法。例如：

> 想试做一个桌面收纳架模型，上层放笔，下层有两个小抽屉。希望能换角度观察，后面还能改尺寸。请先研究适合的制作和查看方式，做一个简单版本，说明会交付哪些文件、怎样打开、需要哪些软件或接口。

也可以把目标放在熟悉的软件里：

> 想在 Chrome 里选中文字后保存摘录、网址和备注。先做一个只在指定页面生效的小扩展，能在本地查看并导出记录。请说明安装方法，以及以后增加摘要功能需要什么连接。

不用先替 AI 选好所有工具，也不用一次做齐每一种版本。先有一个范围明确的小作品，实际打开、操作、修改，再决定要不要继续。转动那个模型，换一份名单，保存一张清单，或者给助手一个新问题——对下一件作品的想法，往往就从这些具体操作里冒出来。
