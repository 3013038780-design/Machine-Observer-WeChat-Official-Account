# 交付物独立专题：表格＋讲解大纲 v2

日期：2026-10-23。状态：待用户审核；取代 outline-v1.md 作为当前大纲，v1 留存。尚未写全文或制作排版。

## 一、本轮为什么调整

用户明确喜欢原表格的具体与清晰，认可“表格加讲解”。v1 将“正文不要百科化”过度解释为限制表格、让全量表只在附件出现，又将全文缩到四个主要作品；这不符合用户希望同时获得广度与解释的阅读体验。

本轮改变的是组织方法：**表格成为正文内容骨架，讲解在表格提供的选择中展开。** 探索新成果的命题保持不变。不因清单完整就认定它不适合正文，也不因用户喜欢表格就让每行都展开长篇技术说明。

“一开始的表格没事”理解为对原有表格形式的认可，不直接推断用户要求开头必须先贴一张超长表。正文表可在短导语之后出现；为手机阅读按导航组拆成几段，每组配讲解。完整原表与 120 条详细目录继续保留，不删除、不重新合并成几个含糊词语。

## 二、写作逻辑

读者起点：已经熟悉一些 AI 成果，但未必想到其他交付物也可以尝试。

文章命题：让读者看见更广的具体作品，知道成果在哪里、怎样使用与需要什么条件，从中找到自己愿意第一次试做的东西。

唯一组织轴：按读者与成果的使用关系递进——**阅读和查阅 → 打开和操作 → 观察和修改空间对象 → 换输入重复运行 → 交办任务。** 这是阅读导航，不是互斥行业分类或能力等级。各组表格列出具体成果，并通过交叉说明承认应用、Agent、接口等可以组合。

每一组采用相同的阅读节奏：

1. 一小段引入，交代这一组可以尝试怎样的成果。
2. 一张具体的探索表，让读者快速浏览并停在感兴趣的行。
3. 选一两个值得解释的例子，写出拿到后怎样操作，再解释表里容易误解的关系。
4. 用下一组新增的使用方式承接，不写成升级或替代建议。

不机械限制每组讲解例子数量，不把前版四个案例视为已经确认的必选项。篇幅由实际阅读决定；不先以减少表格覆盖换取叙述空间。

## 三、正文表格怎么写

原表的“交付类别—可以交付什么—常见载体”直观，保留其具体、可扫描的优点。按用户追加要求补上使用方式、工具与 API 条件；必要时将载体与使用方式放在同一列，避免过宽。

建议正文四列：

| 可以尝试的成果 | 具体能做什么 | 在哪里、怎样使用 | 工具或 API 条件 |
| --- | --- | --- | --- |
| 手机 App | 自己的出行打包清单，能添加、勾选和保存 | 安装在手机，打开后操作 | 对应平台开发工具；离线清单不必调用模型；安装分发条件单独核查 |
| 三维展示 | 可以转动查看的桌面收纳架 | 在兼容查看器或浏览器中观察 | 建模工具＋展示工具；能转动不自动意味着能改尺寸 |
| 证书生成器 | 换一份名单，生成对应的一批证书 | 本地程序或网页入口，指定输入并运行 | 模板和文件生成程序；按规则处理不必调用模型 |

以上是列结构与解释粒度示意，不是正文只保留这三项，也不是已经完成的样例。

正文每一行应指向可辨认成果，不能只写“Agent”“机器人”“API”“插件”。同一作用域的跨平台实现可以在行内交代；实际交付不同则拆行。不按文件后缀重复凑项。

不预先给正文行数上限。先覆盖原表中的成果领域，再用详细目录补充必要细分；去掉的是同义重复和不影响读者认识的实现变体。若正文表与 120 条参考目录详略不同，保留明确对照入口。

## 四、标题与开篇

标题候选继续采用：《让 AI 帮你做点以前没做过的东西》。尚未确认。

开篇核心问题：已经做过网站、文章或图片的人，还可以尝试什么？

用几句具体画面说明：自己的手机小应用、能转动观察的模型、能重新生成文件的程序，都是可以考虑的成果。随后直接进入表格，让读者先看到一批具体选择。不先定义“交付物”，不以旧方法失败或高昂损失作为前提。

## 五、正文大纲

### 第一组：把资料和想法做成可以阅读、查阅和计算的作品

**问题与答案**：资料整理完成后，可以形成怎样的可使用成果？展示文档、数据和媒体等多种表达，不假定所有任务应做同一种版本。

**表格覆盖**：文章与可修订文档、固定版式出版物、电子书、可编辑演示稿、带公式工作簿、数据集、数据库、可搜索知识站、交互报告/看板、计算器/计算笔记本、地图、图片与可编辑设计、音视频及其工程。按成品差异细分，不把所有媒体塞成一行。若一张表过长，就在本组内分段，不砍掉声音、地图等陌生方向。

**讲解候选**：带公式工作簿与预算计算器怎样实际输入和重算；或者把一份资料做成有搜索入口的知识站。用一个主要过程讲透，声音工程的成片/分轨、演示的图片/可编辑对象等关系就近简述。

**与下一组关系**：先展示可阅读查阅的作品，再展示可以进入日常操作环境的应用。

### 第二组：做一个自己能打开、安装或加入常用软件的小工具

**问题与答案**：自己可以做哪些应用，拿到后从哪里使用？让网站、App、小程序、插件都有明确的入口，而不是隐藏在“软件”大类中。

**表格覆盖**：网站/网页工具、可安装网页应用、iOS/Android App、平台小程序、桌面应用、菜单栏/托盘工具、命令行工具、浏览器扩展、编辑器/办公/设计软件插件、游戏与互动作品、可嵌入组件、供程序调用的接口和 SDK。按必要差别拆行，交代接口服务不是人直接点击的界面。

**讲解候选**：个人打包清单的手机/App/小程序入口，或浏览器摘录按钮如何进入原有阅读过程。无需同时制作所有载体。

**必需消歧**：页面原型与可用程序；源码与安装成品；宿主插件与独立应用。API 用一个输入输出解释，例如传入重量和目的地、返回运费；服务工程与已部署状态分开。

**与下一组关系**：从屏幕里的日常工具，进入可以观察和修改空间形状的制作对象。

### 第三组：试着做一个能换角度看、能继续修改的空间对象

**问题与答案**：没有三维或 CAD 经验的人可以从什么成果开始？从观察与小范围修改展开，不默认目标是制造或施工。

**表格覆盖**：三维模型、交互三维展示、可编辑空间场景、参数化模型、尺寸图、零件/装配工程、三维打印与切割准备资料、三维动画；电路工程和设备仿真在相关行给具体对象与边界，不省略为泛称“工程文件”。

**讲解候选**：桌面收纳架从不同方向查看、调整某层高度的过程。房间或会场布局作为相邻例子，按解释需要选用，不因先前讨论就强制全部展开。

**必需消歧**：展示模型、可编辑工程、尺寸图与机器指令；制作软件与查看软件；直接调整与返回源工程修改。工具路径待样例核查，不先宣布某个软件普遍最优。

**与下一组关系**：除了得到对象，也可以留下制作或处理办法，下次换输入继续运行。

### 第四组：给下次的工作留一个能重新运行的办法

**问题与答案**：成果能否包括重复处理的能力？可以交付模板、生成器、批处理程序和已配置工作流，完成状态分别说明。

**表格覆盖**：可复用模板、批量文件处理、名单生成证书/报价单等生成器、数据清洗导入、定时报告、变更监测、事件触发、跨系统同步、可视化工作流、构建检查流程、设备自动化。触发器是运行条件，不冒充新的文件格式。

**讲解候选**：虚构名单生成证书，再换输入运行；结合该例说明模板、程序和启动入口。也可以根据研究改用更具吸引力的实际样例。

**必需消歧**：本次生成结果与可再次运行程序；可导入工作流与已配置自动运行系统。按规则处理通常不必调用模型，制作时用了 AI 与运行时依赖 AI 分开。

**与下一组关系**：已有明确处理规则之后，再解释需要在执行过程中作判断的任务系统，避免一律称“智能机器人”。

### 第五组：Agent、机器人和助手，分别能交付成什么

**问题与答案**：这些名称下面究竟是什么程序、在哪里运行、需要哪些连接？用表格先将容易混淆的东西分清，再用过程解释关系。

**表格覆盖**：平台内角色助手与任务 Agent、本地/服务端研究 Agent、编程/分析 Agent、消息推送机器人、指令查询机器人、附件处理/知识问答机器人、网页/桌面操作程序、实体设备的软件模块；知识问答系统、Skill、MCP 工具服务按组成关系交代。研究、编程是职责，本地/服务端是载体，表格标明是具体组合，不当作互斥分类计数。

**讲解候选**：资料研究助手按问题检索、补查、保存来源与整理结果。再说明把这项能力接到聊天平台，用户可以通过机器人发任务；消息入口与 Agent 执行机制能组合。

**必需消歧**：普通机器人未必调用模型；任务 Agent 需要模型参与判断；模型连接可由平台提供、自建程序接云端或在本地运行；消息平台接口、检索工具、模型接口不是同一件东西。提示词/配置包、运行程序与已连接服务分别说明。

**与结尾关系**：把新名词还原成可使用的东西后，读者可以选适合自己的第一次尝试，不要求所有人搭 Agent。

## 六、结尾：从表里选一个真的想试的东西

不再新增一轮清单。回到读者在表中停下来的某一行，让其描述想做出的东西和使用动作，请 AI 研究合适路径并制作小版本。

保留一段自然交办示例：“想试做一个桌面收纳架模型，希望能换角度看，后面还能改尺寸。先研究适合的制作和查看方式，做简单版本，说明会交付什么、怎样打开、需要哪些工具或接口。”

第一次可以只做到能操作、能查看或能再次运行。随后实际打开、试用，再决定是否深入，不把“变成专业人士”当作文章承诺。
