## 这一版怎样组织

本轮明确三列分工：左栏回答“是什么”，中栏解释“拿到什么、在哪个软件或平台用”，第三栏展示“可以怎样提出要求”。左栏不堆开发语言、框架与后缀；中栏保留必要的具体程度，先解释用途，再列载体，避免拿文件清单代替说明。文件名是说明交付范围的示例，不表示本轮已经制作；同一行列出的几种路线按任务选择，不要求全部交付。选用框架和原生软件是具体候选，不是唯一实现。原生 Figma、PSD、CAD 等文件需要在实际支持的工具中制作、导出并检查，不能仅改后缀。

先看拿到什么，再用具体作品说明它可以是什么样。每行写一类能够明确约定、交给使用者使用的成果；名称后面的例子帮助想象，不继续拆成功能目录。行内可以包含用途不同、但交付与使用方式相近的作品。

分组是阅读导航，不是一套互斥的行业分类；一项项目可以组合多类成果。网站、游戏等名称也不处在同一套软件技术分类中，但分别提供读者熟悉且有明确使用方式的成果入口。不能将导航分组或表格行数宣称为“AI 所能交付的全部种类”。本版不以总数为标题卖点。

拆分依据是拿到的对象、进入方式或后续使用动作存在值得读者认识的差别。只换题材、业务用途、界面功能、触发时间或模型数量，一般不另起一行。一个游戏的背包和存档不拆项；一套可独立导入的游戏资产可以另列。图像成品和分层设计工程分开说明，因为查看成图与继续修改对象是不同的交付要求；源文件本身不是包揽所有类别的新类别。

网站里的计算器、看板、库存管理都可以是完整作品，在本清单作为网页应用的具体例子，不按功能逐个扩项。iOS/Android、菜单栏/托盘、本地/云端、定时/事件触发，也分别作为平台、入口、部署和启动条件，不再靠这些属性增加行数。

以下例子是供交办和选材的设计示例，未在本轮实际制作或验证。工具与接口的必要条件集中在每组后，制作时用了 AI 不表示成品运行必须接模型。

## 一、能直接打开或进入的应用

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 网站与网页应用 | 例如 index.html、CSS、JavaScript、图片和 data.json，交整份网页工程；需要后端的项目另附服务代码和启动方法。作品集、比较报告、计算器、看板、库存系统仍为同一行的例子。 | 做一个 HTML 产品比较网页，交 HTML、CSS、JavaScript、数据和素材；能筛选并查看来源，附启动方法。 |

| 电脑应用 | 例如 Electron 工程（package.json、应用代码、界面与素材），按选定系统构建可运行版本或安装包；窗口、菜单栏、托盘是入口选择。 | 做一个 Windows 图片整理工具，采用 Electron，交完整工程和可运行版本，能预览再执行改名。 |

## 三、能重复执行、接入或复用的程序工程

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 批处理程序 | 例如 generate_certificates.py、requirements.txt、名单 CSV、证书模板与输出 PDF；或 Node.js 工程。照片批处理、网页录入、数据清洗仍作为用途例子。 | 用 Python 做证书生成程序，交 .py、依赖、CSV 样例和模板，附一条可执行的启动命令。 |
| 自动化工作流与快捷指令 | 例如 n8n 导出的工作流 JSON、节点与连接说明，导入 n8n 后配置执行；若做苹果快捷指令，交可导入的快捷指令及说明。两者不互换。 | 把取数、清洗和生成报告做成 n8n 工作流，交可导入 JSON、节点依赖与连接说明。 |
| 接口服务（API） | 一段运行中的服务程序，其他网页或 App 可以把数据发给它并取回结果。例如用 FastAPI 做运费计算服务，交 Python 工程、依赖、启动方法和调用样例。 | 做一个能让网页调用的运费计算服务，按重量和目的地返回明细，附代码、启动方法和调用例子。 |
| 可复用代码包 | 给别的程序拿来使用的一包代码。例如 Python 校验规则包，交源码、安装说明和使用样例；若是连接某项服务的 SDK，还要说明它依赖哪项服务。 | 把这些校验规则做成 Python 软件包，交源码、pyproject.toml、安装与调用样例。 |
| 可嵌入的界面组件 | 能装进网页项目的一块真实界面，例如 React 预约日历。交 TypeScript 代码、样式、演示页面和接入说明；开发者把它接进自己的程序。 | 做一个 React 预约日历组件，交 TypeScript 源码、样式、演示和输入输出说明。 |

条件：程序需要相应运行时，工作流依赖兼容平台与执行环境，服务需要实际运行位置和调用约定。SDK 不代表服务已经开通；流程定义不代表连接已配好。固定步骤的网页/桌面自动操作程序也可放在处理程序中，要说明控制工具与访问条件；采用模型判断下一步时见任务 Agent。CLI 是处理程序的一种入口，定时、事件触发是启动方式，持续运行是部署要求，不分别扩项。构建/测试/部署流程也可作为工作流实例。

## 四、能继续接任务的 AI 助手及其能力包

本组保留 Agent、机器人这些读者会主动寻找的入口，但按实际交出的对象写。下列可以组成同一个系统，不能把它们累计成多个互斥的“AI 产品种类”。

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 平台里的专用助手 | 例如在 Dify 里配置的课程答疑助手，在该平台打开并提问。交助手配置、资料与连接说明；其中 DSL 是可导入的配置文件，不代表资料和模型账号也一起迁移。 | 在 Dify 做课程答疑助手，使用这些资料，交可复用配置、资料清单和模型设置说明。 |
| 能继续接任务的助手（Agent） | 例如自己电脑上的 Python 研究助手：输入新问题，它能检索、补查并保存结果。交运行程序、工具连接、依赖、配置样例和打开方法；若有网页入口，说明页面和执行程序各在哪里。 | 做一个在我电脑上运行的研究助手，能接新问题并补查来源，交程序、打开方法和模型连接说明。 |
| 聊天机器人 | 例如飞书里的订单表检查机器人：人在飞书发文件，程序处理后回传结果。交飞书应用配置、Python/Node.js 服务端代码、权限与部署说明。微信版要写明公众号等具体入口；自己的网页/App聊天应用放第一组，不在这里再算一项。 | 做一个飞书机器人，我发订单表，它检查后返回文件，交运行代码、平台配置和启动说明。 |
| AI 技能包（Skill） | 让兼容的 AI 助手以后能重复使用的一套做事方法。例如报告制作技能包，包含任务说明，可附脚本、模板和样例。交完整文件包，并说明装进哪个助手、怎样调用。SKILL.md 只是包内那份说明文件的名字。 | 把这套报告做法整理成可复用的 AI 技能包，带模板和需要的脚本，说明给哪个助手用、怎么安装和调用。 |
| 给 AI 接工具的服务（MCP） | 例如让兼容的 AI 应用调用库存查询程序。交 Python/TypeScript 工具服务、启动方法与客户端连接样例；MCP 是连接协议，库存查询等业务能力仍要有实际程序和数据。 | 让兼容的 AI 应用能查这份库存，做成 MCP 工具服务，交代码、启动和连接方法。 |
| 经过专门调整的模型 | 例如针对某项分类任务调整的模型，或需要配合原模型加载的一组适配文件。交适配权重、原模型名称、加载脚本与评估结果；LoRA 是可能采用的适配方法之一。 | 先判断这些样本是否值得微调；合适时交调整成果、原模型信息、加载方法和效果检查。 |

消息入口补充：上表用飞书自建应用机器人作为可以明确交办的主例。微信需区分公众号消息入口、企业微信、微信小程序里的聊天页和个人微信会话；自建网页/App聊天按第一组应用说明界面与后端，不在机器人行重复列。小红书小程序入口不等于任意账号私信机器人，具体私信能力、主体和权限尚需专项核查，本版不作可接承诺。

条件：任务 Agent 要有模型、执行机制、工具及文件/状态存储；平台可提供部分条件，自建时按任务选择云端或本地模型。资料问答可做成网页应用、平台助手或消息机器人，检索组件随对应系统交付，不再按“问答用途”另列产品种类。浏览器/桌面操作要控制工具；机器人要消息接口，固定规则机器人可以不用模型。多 Agent、持续任务、知识检索属于机制或组成要求，写进系统说明，不再分别列一行。模型适配不同于接入资料检索，需单独评估数据、工具和算力。

## 五、能导入、查询或重新计算的数据与资料

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 整理好的资料库 | 例如分主题文件夹、原文 PDF/Markdown、sources.csv 和 README 索引；在文件管理器或 Markdown 工具中查阅。 | 整理这些资料，交分主题目录、原文、sources.csv 和 Markdown 索引，保留来源。 |
| 整理好的数据 | 例如 products.csv、字段说明和异常记录表；在 Excel、数据库或分析程序中导入使用，按结构选合适格式，不要求全交。 | 清洗产品记录，交 UTF-8 CSV、字段和单位说明、来源及异常行清单。 |

| 带公式的表格 | 例如 budget.xlsx，保留可编辑输入、公式、图表和必要说明；在兼容 Excel 等软件中重算，不交成图片表格。 | 做预算 Excel，交 .xlsx，人数和场地费可改，公式与图表保留并标清输入。 |
| 可重跑的分析笔记本 | 例如 analysis.ipynb、数据目录、requirements.txt 和结果；在 Jupyter 中运行，换数据重做。 | 把分析交成 Jupyter .ipynb，附数据、Python 依赖和从头运行的方法。 |
| 可导入日历等软件的记录 | 例如课程表 .ics 导入日历、联系人 .vcf 导入通讯录，或 BibTeX .bib 导入支持的文献工具；按目标交一种或约定组合。 | 把课程表交成可导入日历的 .ics，明确时区和重复规则，附验证样例。 |

条件：字段与来源是数据成果的说明，检查程序属于第三组，检查结果随数据一起交付。数据库和带操作界面的业务应用不同。日历/联系人/书目不是按后缀凑数，而是让人看到内容可以直接进入原来使用的软件。语义检索索引若随问答系统使用，作为系统配套材料说明，不再与原资料库重复计为整套知识产品。

## 六、能阅读、填写、放映或印出来的材料

| 可以交付什么 | 拿到什么、在哪里用、具体例子 | 可以这样跟 AI 说 |
| --- | --- | --- |
| 文稿与报告 | 例如 research.docx 或 article.md、来源表与素材；在 Word 或 Markdown 编辑器继续批注和修订。 | 按这个命题写 Word 报告，交 .docx 和来源表，保留可编辑正文与图表。 |
| PDF 手册与画册 | 例如 handbook.pdf，加实际采用的 Word、InDesign 或 HTML 排版源；PDF 用来阅读打印，源文件用来修改。 | 做有目录和页码的 PDF 手册，另交实际排版源、字体素材说明和打印尺寸。 |
| 电子书 | 例如 book.epub、章节 Markdown/HTML 和图片目录，导入支持 EPUB 的阅读器调字号与跳章节。 | 把这个系列做成 book.epub，保留章节源稿和图片，检查目录与变字号后的阅读效果。 |
| 演示文稿 | 例如 course.pptx，保留文字框、图表、图形和讲者备注；在兼容 PowerPoint 的软件修改与放映。 | 做课程 PowerPoint，交可编辑 .pptx，保留图表对象和讲者备注，不只嵌页面截图。 |
| 可填写的表单 | 例如 registration.pdf，字段可填并保存，附制作源和目标阅读器测试；不是把空白横线画进 PDF 就完成。 | 做含填写字段的报名 PDF，在约定阅读器检查填写与保存，附制作源。 |
| 可打印的卡片与教具 | 例如识别卡正反面 PDF、裁切线、SVG 或实际排版源，写明纸张尺寸和双面规则；打印裁切使用。 | 做植物识别卡，交 A4 正反面打印 PDF、裁切线、可编辑源和组装说明。 |

条件：这些区分对应不同使用动作，不是看到不同后缀就单列。Word 和 Markdown 可以作为文字稿的不同载体，不分别列项；固定版式与可重排阅读需要不同检查。题库的结构化记录归数据集，题册和教学卡归本组。

## 随成果交付的说明，不再重复列成成果种类

以下条件放回每项成果旁边，按任务说明，不再占一组“其他交付物”：

- **编辑与复用**：是否保留可编辑源、模板、素材、参数和修改方法。独立模板库可作为对应文档、设计或组件成果交付，但“可复用”不是新形态。
- **运行与安装**：适用平台、依赖、启动方法、入口、安装包和配置；本地、云端、定时、事件触发都是条件或方式。
- **连接与模型**：模型由谁提供，是否需要云端/本地模型接口、业务接口、宿主接口、设备或账号；“不需要云端模型接口”不表示没有软件接口。
- **核对与接管**：来源、数据版本、样例、实际检查结果、已知边界和交接说明。独立委托的研究报告、检查报告仍可作为文档成果；作为配套说明时不重复计数。
- **交付状态**：方案、源工程、运行版、已连接系统分别交到哪一步。原位修改要提供可核对的结果，仓库或压缩包只是交接容器，不是另一种成果。

## 组织自检

1. 网页应用可以承载计算、看板和管理任务，例子丰富但不按每项功能扩张。
2. 游戏保持完整成果入口，不列背包、存档和排行榜；独立资产、配乐和工程按其实际使用方式在对应组介绍。
3. Agent 不再按研究/编程/分析，也不按本地/云端/持续/多代理分别造新条目；机器人不按通知/查询/附件/问答分别造新条目。
4. 自动化不按触发器拆项；实际交付脚本、可导入流程或服务时才明确对象。
5. 分组服务阅读，行数不代表互斥类别数量；先看覆盖是否足够、条目是否具体，再决定文章应保留哪些，不用数字证明全面。
