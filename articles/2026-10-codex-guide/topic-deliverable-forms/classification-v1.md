# 按实际成果形态分类：方案 v1

日期：2026-10-23。状态：待用户审核。此次只调整分类，article-v1.md 不变，不据此直接修改全文或排版。

## 一、统一依据与分类单位

统一问题：**交付的对象本身是什么？** 先识别文档、数据、设计、媒体、工程、应用、组件或服务，再记录任务和运行方式。

分类单位是“可以单独指明的交付对象”，不是整个项目。一项收纳架任务可能包含效果图、CAD 工程、交互展示和说明文档；它是多项成果的组合，不必强塞到唯一类别。完整软件也可含界面应用、接口服务、数据库与插件。

本方案是供这篇文章使用的编辑分类，不是官方标准或软件/文件的形式化本体。采用八个主要类别及具体子类，以交付约定识别对象；跨领域项目拆分组成，避免靠扩大“其他”或重复计数来维持表面互斥。

三个约束：

- 同一类允许成品与可编辑版本；“是否可编辑”另记，不把可编辑文档挪入一个包揽全部源文件的工程类。
- 文件后缀只是线索。HTML 可能是文章，也可能是程序；JSON 可能是数据，也可能是配置。
- 软件源码按它实现的对象归类：App 源码是应用的源版本，API 服务源码是服务的源版本。不能将所有源码统一丢进“代码包”，也不能以是否部署改变对象类型。

## 二、八个主要类别

| 编号／主类 | 为什么这样分：识别的是哪种对象 | 具体交付物与子类 | 如何使用／主要边界 |
| --- | --- | --- | --- |
| C1 文档、演示与出版材料 | 核心对象是文章、页面、章节、幻灯片、题目或版式化文字材料 | 文章、报告、方案、说明书、Word/在线文档、Markdown；PPT/网页演示；PDF 手册、EPUB；讲义、题册、分镜文字稿、README、测试报告；可填写文件表单 | 阅读、修订、批注、放映、打印或填写。可编辑 PPT 仍在此类；在线报名应用归 C6；题库若交结构化记录另列 C2 |
| C2 数据、工作簿与计算资料 | 核心对象是可导入、查询、计算或复核的记录和数据关系 | CSV/JSON 等数据集、字段字典、标注/评估数据；数据库文件、表结构、查询与视图；带公式工作簿；计算笔记本；日历/联系人/书目导入记录；地理数据、检索索引 | 导入、查询、改输入重算或运行笔记本。数据快照不等于数据库服务；具备完整操作界面的业务系统另列 C6，长期可调用的数据服务另列 C8 |
| C3 图像、平面设计与图解 | 核心对象是图像、路径、图层、画布、图形关系或界面设计对象 | 照片/插画、透明素材、图标、矢量图；海报、品牌设计稿；流程图、关系图、信息图、静态地图；界面设计稿、设计组件、设计变量、可点击设计原型 | 查看、缩放、编辑对象、导出。原型工具中的跳转仍可是一份设计成果；若交付真实运行的应用/网页则归 C6。程序组件另列 C7 |
| C4 音频、视频与动画材料 | 核心对象是声音、镜头、时间轴、音轨、帧或动作时间序列 | 配音、播客、音乐、音效；音频分轨和工程、MIDI；成片、录屏、字幕与时间轴；剪辑工程、二维动画、动态图解成品 | 播放，或在兼容制作工具中调整时间、图层/轨道再导出。三维角色及场景源工程归 C5；动画生成程序归 C6；它导出的动画另列 C4 |
| C5 三维模型、图纸与设计仿真工程 | 核心对象是几何、尺寸、约束、零件关系、电路、空间图层或仿真模型 | 三维资产、场景、角色绑定工程；CAD 尺寸图、参数化零件、装配；打印/切割模型、CAM 工程及设备对应指令；电路/PCB 工程；GIS 工程；设备/科学仿真工程 | 在对应工具中查看、修改、重算或运行仿真。这里的工程指领域设计对象，不是所有“项目目录”；交互展示应用归 C6，渲染图/视频归 C3/C4，实物另有制造交付 |
| C6 应用与可执行处理程序 | 核心对象是一件面向使用者启动或操作、完成任务的软件作品 | 网站、网页应用、本地交互报告、看板、计算器；PWA、App、小程序；桌面/菜单栏工具、CLI、批处理和生成器；游戏、互动课程、AR/VR 应用；设备固件、独立控制程序 | 从网址、图标、命令或设备启动。按交付物保留运行版与源工程。后台与数据可作为组成另列；应用“依赖操作系统/平台”不自动变成 C7 插件 |
| C7 可集成组件、扩展与配置包 | 核心对象是接入指定宿主、项目或执行环境后生效的扩展单元 | 浏览器/办公/设计/编辑器插件、宏；函数库、SDK、代码组件；Skill；助手角色/工具配置；可导入工作流与快捷指令；模型适配器/权重及加载配置；设备驱动/控制库 | 安装、导入、引用或加载到目标环境；宿主和依赖要明确。完整小程序是 C6 应用；插件给既有软件增加能力。训练数据归 C2，托管推理服务归 C8 |
| C8 后台服务与可调用运行系统 | 核心对象是供前端、设备、其他程序或事件调用/驱动的后端服务 | 查询、运费计算、文件转换、预约处理 API；webhook 接收端；消息机器人后台；检索/推理服务；任务执行、监测、同步后台；数据库服务；本地/远程 MCP 服务 | 通过接口、消息、事件或调度接入；写明服务进程在哪里、怎样连接和管理。可交服务工程，也可交已运行实例；两者是同类对象的不同交付状态 |

八类中的子类还会细分。例如 C6 中 App、平台小程序、桌面程序、CLI 各有自己的入口，C8 中文件转换与消息后台各有自己的输入输出。不能因主类减少，就将原来具体条目都压成八个名称。

当前范围以数字成果为主。若约定交付打印好的教具、制造好的收纳架或装配好的机器人，必须另加“实体制品”类并包含实际制作与交接；不能用 PDF、STL 或控制代码代替实物。此处列明边界，不扩大本篇为制造教程。

## 三、容易重复的对象，怎样判定

| 同一个熟悉名称 | 实际拿到什么 | 主归属 |
| --- | --- | --- |
| 报告 | 文章、DOCX、阅读型 HTML/PDF | C1；需要计算的数据/工作簿另列 C2 |
| 交互报告 | 有筛选、选择、重新计算等程序行为的页面 | C6，任务标签为“报告/分析”；网页中的图片、数据不重复算成另一个应用 |
| 表单 | 可以填写的文件 | C1；收集、存储、管理提交结果的在线表单是 C6，后台可另列 C8 |
| 地图 | 静态图、空间数据、GIS 工程、交互地图页面 | 分别为 C3、C2、C5、C6；不再设一个包揽四者的“地图类” |
| 三维展示 | 模型文件、渲染视频、可转动的网页 | 分别为 C5、C4、C6；网页含模型时记录组成即可 |
| 参数化设计 | CAD 参数工程，或独立的几何生成程序 | 前者 C5；后者 C6，输出模型另列 C5。不能只看是否含脚本 |
| 知识库 | 资料文档、数据/索引、搜索站、问答应用或检索接口 | 分别按 C1/C2/C6/C8 记录，先拆实物对象，再给“知识库”用途标签 |
| 模板 | 文档模板、设计模板、软件脚手架 | 文档模板 C1，设计模板 C3，三维模板 C5；供集成的脚手架 C7。生成器本身是 C6/C8 |
| 模型 | 三维几何、机器学习权重、仿真模型 | 分别为 C5、C7、C5；“模型”不能单独作为无说明的条目 |
| 测试 | 检查报告、评估数据、可运行测试工具 | 分别为 C1、C2、C6/C7；按交付对象而非“验证”用途另建大类 |

其中阅读型 HTML 可以含目录和链接；不因存在链接就自动视为应用。交互报告依靠代码执行筛选、选择或计算作为主要使用能力时归 C6。具体边界依用户约定的交付对象记录，不追求仅凭后缀自动分完所有项目。

## 四、Agent、机器人、自动化怎样放

三者不再作为第九、第十、第十一种主成果形态，也不从清单消失。它们会保留为明确名称与横向说明；每个具体条目必须带上实际交付载体。

| 跨类别名称 | 它说明哪一层信息 | 可能落入的主要类别 | 具体例子 |
| --- | --- | --- | --- |
| Agent | 模型怎样参与选择动作、调用工具和根据反馈继续执行 | 完整应用 C6；配置/插件/能力单元 C7；任务执行服务 C8 | 桌面研究 Agent；编辑器内编程 Agent 扩展；平台助手配置；接受任务的研究后台 |
| 机器人（软件） | 自动承担的角色，或接收消息/执行操作的入口；机制要另记 | 用户启动的操作程序 C6；平台配置/插件 C7；消息与处理后台 C8 | 网页录入程序；机器人配置；查询机器人服务。固定规则和 Agent 均可采用这些入口 |
| 实体机器人相关成果 | 硬件用途，仍需说交的是何种数字对象 | 机械/电路/仿真工程 C5；固件和独立控制程序 C6；驱动/库 C7；远程管理服务 C8 | 仿真场景＋传感器节点程序；不是仅写“交付机器人” |
| 自动化 | 工作怎样由程序执行，以及手动、定时或事件启动的方式 | 脚本/处理程序 C6；可导入流程/快捷指令 C7；后台执行系统 C8 | 本地照片批处理；n8n 工作流定义；自动取数并发报告的服务 |

Agent 的架构定义、消息平台连接及本地/云端模型条件沿用已有研究来源，未在此提出新的厂商实现结论。这一分类方案本身是编辑设计。

“自动化＋Agent＋机器人”可能同时成立。例如：服务器按时启动研究 Agent，完成后通过消息机器人发送结果。这里按时启动是触发条件，Agent 是执行机制，机器人是消息入口；实际软件交付可能是一套 C8 服务及 C7 配置，报告输出另列 C1。

成品报告可以注明“由 Agent 生成”，但它的使用不因此需要模型。尤其要区分**交付 Agent 产出的报告**与**交付以后还能接新任务的 Agent 系统**。

## 五、实际清单需要同时保留的字段

| 字段 | 回答的问题 | 示例 |
| --- | --- | --- |
| 主成果形态 | 对象本身是什么？ | C6 桌面应用 |
| 具体名称与用途 | 用户想用它做什么？ | 资料研究助手 |
| 入口与运行位置 | 从哪里用、程序在哪里执行？ | 桌面窗口；本机执行 |
| 工作机制 | 规则、固定流程还是模型选择动作？ | Agent 执行循环 |
| 启动方式 | 什么时候开始？ | 人工提交一个问题 |
| 所需工具与连接 | 需要哪些软件、模型和业务接口？ | 本地/云端模型、浏览/检索工具、文件存储 |
| 交付组成与状态 | 交了哪些部分，哪些已验证？ | 源工程、运行版、配置、操作说明；完成单次任务验证 |

“是否可编辑”“可重复使用”“本地/云端”“是否调用模型”“源文件/运行版/已部署”全部作为说明字段，不再反复升格为主类。Git 仓库、压缩包、容器是保存/打包/运行封装方式；已保存修改、PR、系统内更新是交付动作与证据，也不另起主类。

## 六、三个完整归类示例

### 1. 桌面收纳架

效果图 C3；参数化 CAD 工程 C5；可转动展示页 C6；尺寸说明 C1 或尺寸图 C5，按实际对象区分。若另交独立生成程序，记 C6。用途标签为收纳设计，无需因出现三维就把整项交付全部归 C5。

### 2. 证书生成

证书 PDF 和文档模板 C1；名单 C2；独立生成程序 C6。若交可导入平台的流程定义，记 C7；若交承接生成任务的后台，记 C8。自动化记录为规则执行，可按需标手动或事件触发，不另加“自动化文件”类别。

### 3. 聊天里的研究助手

若交的是现有平台助手配置，记 C7；若交自建网页应用，记 C6，配套任务后台记 C8。消息机器人后台记 C8，接入配置另记 C7。模型、检索和消息连接是依赖；Agent 是执行机制。输出报告 C1，来源数据 C2。交付范围须明确，不默认每种版本都要制作。
