# 让 AI 帮你做点以前没做过的东西

标题候选｜完整纯文字稿 v2，待审阅｜2026-10-23

会让 AI 写文章、做图片，也许已经做过自己的网页。下一次，还想试点什么？

一个装在手机里的小应用，一个收到表格就能返回处理结果的机器人，一个能转到背面看的收纳架模型，或者一套换了名单就能重新生成证书的程序，都可以成为下一件想试的作品。

有些东西以前没有想到，往往是因为没有接触过它的制作方式。认识更多具体成果，就多了几个可以开始的地方。

下面是一份按常见名称和制作领域展开的探索清单。可以从熟悉的地方读，也可以直接找到感兴趣的一组。网站、Agent、机器人、自动化之间会有交叉：同一个研究助手可以放在网页里，也可以接进聊天平台。遇到这种关系，表格和讲解会就近说明。

每一项都回答五个问题：是什么、交付什么、载体在哪里、怎样使用、需要哪些工具或接口。文中的作品是说明性设计示例；实际制作路径要结合可用软件、平台和设备确定。

先分清一个关系：**制作时用了 AI，成品运行时未必需要 AI。** 图片和视频生成后可以直接播放；清单、计算器和批处理程序也可以按规则运行。需要模型参与判断时，才进一步安排模型连接。表中的“本地可用”或“无需外部 API”只针对所描述的基础用法。

## 一、网站与浏览器中的成果

浏览器里可以放文章，也可以放一件能筛选、比较、计算的小作品。先从最容易打开的入口开始。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 展示网站 | 作品集、产品介绍或活动信息；交付网页工程和静态成品 | 浏览器显示；可由网站托管服务提供 | 打开链接浏览；维护者改内容再发布 | HTML/CSS 或网页框架；纯展示无需外部模型或业务 API |
| 本地交互报告 | 可筛选产品、查看来源和图表的报告；交付页面及数据 | 本地文件，或本地静态服务＋浏览器 | 打开后筛选、比较、导出选择 | JavaScript、图表库；数据随附时无需外部 API；部分资源加载需本地服务 |
| 计算器与模拟器 | 调整预算、尺寸或假设后重算的工具；交付逻辑、界面和样例 | 浏览器；简单计算可全在本机执行 | 输入数值，查看结果和计算依据 | JavaScript 等；规则计算无需模型；实时外部数据按需连接 |
| 有数据记录的业务应用 | 预约、库存或项目管理系统；交付前端、后端、数据库结构 | 浏览器＋本地或服务器后台 | 登录、录入、查询并修改记录 | Web 框架、数据库；通常有自建接口，外部支付/短信等按功能接入；模型非必需 |
| 可安装网页应用 PWA | 可以安装入口、按设计支持部分离线能力的网页应用；交付网页工程及相关配置 | 支持该能力的浏览器和系统；后台按功能设置 | 访问后安装或添加入口，再启动使用 | Web manifest、按需缓存机制；安装体验因平台而异；不等同原生 App；模型非必需 |
| 数据看板 | 汇总指标、筛选维度、下钻明细；交付页面/看板工程与数据连接规则 | 浏览器或 BI 平台；数据处理在本地或服务端 | 选择时间和范围、看趋势与明细 | 图表库或 BI 工具；本地快照无需外部 API，实时看板需数据连接；不自动具备“实时”能力 |

例如，想比较几款雨衣，可以设计一个小页面：图片和关键参数并排，勾选“能覆盖背包”，只看符合条件的款式；点开一条结论，就能回到来源。

做完比较后，还可以让页面导出保留名单，交给 AI 继续研究。点击本身不会自动变成 AI 知道的信息，需要保存、导出或实际连接。第一次可以只放几款产品，亲自筛选一次，再决定要不要增加功能。

## 二、手机、桌面和平台内应用

做过网站之后，还可以试着把一个小想法放进手机、电脑菜单栏或常用平台，让它有一个固定入口。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| iPhone/iPad App | 可安装的记录、学习等应用；交付工程、构建说明和约定的测试/安装版本 | 手机或平板；可选服务器后台 | 安装后触控、拍照或离线记录 | Xcode、Apple 平台 SDK；云同步/模型按需接入；签名与分发另核，不把源码等同已上架 |
| Android App | Android 上运行的应用；交付工程、构建配置和安装/分发产物 | Android 手机、平板或约定设备 | 安装后使用设备功能和界面 | Android SDK、构建工具，Android Studio 为常见开发入口；基础离线功能无需外部 API |
| 微信小程序 | 微信内的预约、查询或活动应用；交付小程序工程及所需后台 | 微信客户端＋可选云开发/自建后台 | 搜索或扫码进入，在平台内操作 | 微信开发工具与平台接口；模型非必需；按所用功能确认平台与发布条件 |
| 其他平台小程序/轻应用 | 指定平台内运行的工具；交付适配该平台的工程、配置和连接说明 | 支付宝、抖音或企业协作平台等指定宿主 | 从平台入口进入、填表或处理任务 | 对应平台 SDK/API；不同平台分别适配，开发与发布条件分别确认 |
| 桌面窗口应用 | 批量文件工具、笔记工具等；交付项目和目标系统安装包 | Windows、macOS 或 Linux 电脑 | 打开窗口，选文件、执行并查看结果 | 系统原生工具链或 Electron/Tauri 等；框架为候选路线；本地处理无需外部 API |
| 菜单栏/托盘工具 | 常驻入口的剪贴板、计时或状态工具；交付应用及启动配置 | 电脑菜单栏/托盘，程序在本机运行 | 点图标或热键执行小任务 | 操作系统接口与打包工具；读取剪贴板等需对应权限；模型非必需 |
| 系统小组件与快捷操作 | 日程卡片、快速记录、文件右键动作；交付扩展或可导入指令 | 指定系统的小组件/快捷指令/文件管理器 | 点卡片、热键或右键启动 | 对应系统能力与权限；接口按功能决定；可组合第六组流程 |
| 命令行工具 CLI | 用命令和参数操作文件、数据或服务；交付可执行工具/脚本包及帮助说明 | 电脑或服务器的终端与运行环境 | 输入命令，指定文件/参数，查看输出和退出状态 | Python/Node.js 等或编译语言工具链；按功能连接模型/业务服务，基础本地工具无需外部 API |

可以试做一份自己的出行打包清单。新建“周末露营”，加入帐篷、头灯和雨衣；装进包里的物品点一下勾选，下次出行复制清单继续用。

做成网页，就从浏览器进入；做成 App，就从手机图标打开；做成微信小程序，就在微信里使用。第一次选一种载体即可。保存到本机和跨设备同步需要不同设计，普通勾选功能则可以完全按规则运行。微信官方示例提供独立的小程序工程与开发工具入口，网页与小程序仍需分别适配。[微信小程序示例](https://github.com/wechat-miniprogram/miniprogram-demo)

## 三、扩展、插件与可嵌入组件

有些作品适合长在已有软件里：网页上的摘录按钮、表格里的检查命令、设计软件中的批量操作，都可以单独做出来。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 浏览器扩展 | 给网页增加摘录、标注或批量操作；交付扩展工程、清单和安装产物 | 浏览器扩展栏、侧栏或网页中 | 安装后点按钮或在页面触发 | 浏览器扩展 API、页面脚本；联网/模型按需；所需页面权限要与用途对应 |
| 编辑器扩展 | 格式化、项目导航、检查或辅助编程；交付宿主扩展包 | 指定代码编辑器的扩展运行环境 | 安装后执行命令或打开面板 | 编辑器扩展 API；AI 功能可用宿主模型接口或另接模型，普通扩展无需模型 |
| 办公软件插件/宏 | 在文档或表格中整理、检查、生成内容；交付插件工程或宏及模板 | 指定办公软件内部 | 从菜单/侧栏执行，或触发宏 | Office JS、VBA 或目标套件接口等候选；不同平台支持范围不同；通常无需模型 |
| 设计/三维软件插件 | 批量排版、建模或导出；交付插件、脚本和示例工程 | 指定设计或三维软件 | 安装后执行宿主内命令 | 对应软件脚本/插件 API；无需默认购买模型 API；具体版本兼容另核 |
| 网站系统插件 | 给内容管理或电商系统加功能；交付插件包、设置与迁移说明 | 指定网站系统的服务端或管理界面 | 安装、配置，在站点使用 | 宿主插件接口、后端环境；外部业务连接按功能确定；不是浏览器扩展 |
| 可嵌入界面组件 | 预约日历、图表、上传器等复用模块；交付组件包、样例与接口说明 | 被集成的网页/App 项目中 | 开发者导入并接入数据 | 相应界面框架、构建工具；数据接口按宿主约定；不是完整应用 |

设想阅读文章时，选中一段文字，点一下按钮，就把摘录、网址和备注保存起来。可以先做一个只在指定网页生效的扩展，试试是否顺手，再增加导出或同步。

只保存原文和备注，可以不调用模型；要自动摘要，再加相应连接。Chrome 官方教程展示了给页面加入阅读时间提示的小扩展，类似的“小功能”本身就能成为完整作品。[Chrome 扩展教程](https://developer.chrome.com/docs/extensions/get-started/tutorial/scripts-on-every-tab)

这里的插件要写出宿主：浏览器扩展、办公宏和三维软件插件各有自己的接口与安装方法，不能只交一个叫“插件”的压缩包。

## 四、Agent：按任务执行方式与实际载体展开

Agent 这个名称下面，可能是平台中的一个助手，也可能是自己电脑上的程序，或者服务器上的任务系统。先看具体交付，再理解它怎样工作。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 平台内任务 Agent | 在现有平台中调用工具推进任务；交付角色/目标配置、工具连接与样例 | 平台的运行服务；用户从平台界面进入 | 选助手、给任务、查看过程或回答追问 | 平台须支持相应工具与执行机制；模型可由平台供给；业务工具需连接；未必需用户另配模型密钥 |
| 本地资料研究 Agent | 检索材料、补查缺口、保存来源并形成结果；交付程序、工具与运行配置 | 本机进程＋终端/本地页面 | 指定问题和资料范围，运行后审阅报告与来源 | Python/JavaScript 等运行时；云端模型 API 或合适的本地模型；网络研究需搜索/浏览连接，本地研究可只读文件 |
| 编程 Agent | 读项目、改代码、运行检查并根据反馈继续；交付专用执行程序或宿主配置及验证例子 | 本地工程环境或隔离的云端执行环境 | 给出改动目标，审阅代码差异和测试结果 | 模型、文件/终端/测试工具；仓库托管接口按需求接入；交付“用 Agent 改好的代码”与“Agent 系统”是两项不同成果 |
| 数据分析 Agent | 判断分析步骤，调用计算工具并检查结果；交付分析程序及受控数据连接 | 本机分析环境或服务器，配聊天/任务界面 | 提交问题和数据，查看分析过程、图表和可复现文件 | 模型、本地计算库/SQL 工具；数据库连接按需；不能只交一份报告就称已交付 Agent |
| 浏览器操作 Agent | 根据页面反馈选择点击、输入或导航；交付执行程序、浏览工具和任务配置 | 有浏览器的电脑/服务器；任务入口可为网页 | 给目标，在关键节点确认或接管 | 模型＋浏览器控制/观察工具；可走网页界面，不一定有目标网站 API；需可用登录与访问条件 |
| 工单处理 Agent | 判断工单，检索政策、查询业务并起草/执行动作；交付应用与工具连接 | 服务端＋客服工作台/消息入口 | 新工单触发，或人工指派；检查处理记录 | 模型、工单/订单等业务接口或连接器、权限与审计；对外动作范围要明确 |
| 桌面操作 Agent | 通过屏幕、控件和应用工具推进本机任务；交付操作程序与任务配置 | 获准访问应用的桌面运行环境 | 给任务、观察执行，需要时接管 | 模型、截图/无障碍/应用控制工具；不要求每个应用均有网络 API；不能只交提示词 |
| 持续任务 Agent 服务 | 接收任务、排队执行、暂停/恢复并记录状态；交付服务工程与运行配置 | 服务器或常开的本机；网页/API 为入口 | 提交任务后查看状态、补充信息、取结果 | 模型连接、执行器、状态存储；队列/调度按规模选择；模型本身不会承担持久运行 |
| 多 Agent 协作系统 | 多个职责单元协作，统一分配任务和汇总；交付编排程序与各角色配置 | 本地或服务端进程，入口按产品设计 | 提交一个任务，查看分工、结果及汇总 | 模型、通信/编排逻辑、共享状态及工具；框架可选；多个提示词文件本身不等于运行中的协作系统 |
| 平台角色助手与配置 | 固定角色、资料与输出约定；交付提示词或平台助手配置 | 指定平台或自建聊天应用 | 导入/选择助手后对话 | 需要平台模型或自行连接模型；无自主执行时不称任务 Agent |

设想做一个资料研究助手：接到问题，先检索指定材料；发现关键数字没有出处，就继续补查；资料足够后整理结论并保存来源。模型参与决定下一步，程序负责调用工具、取得反馈，再把结果带入后续判断。这是本文使用的任务 Agent 含义。[Agent 与工作流的区分](https://www.anthropic.com/research/building-effective-agents)

它可以运行在本机，通过终端或本地页面接任务；也可以运行在服务器，供网页调用。模型可能由现有平台提供，也可能连接云端服务或合适的本地模型。本地模型也有调用接口，“不接云端 API”不等于程序内部没有接口。[Ollama 本地与云端接口](https://docs.ollama.com/api/introduction)

因此，想试做 Agent 时，可以先限定一个问题、一组资料和一次执行。拿到的应包括使用入口、执行程序或平台配置，以及所需工具和模型的说明。只有一份角色提示词时，应明确它还依赖哪个平台；只有一份研究报告时，也不能当作已经交付了以后还能接任务的助手。

## 五、机器人：消息入口、自动操作和实体设备分别写

“机器人”并不一定意味着大模型，也不一定有实体外形。这里先看会话和软件操作中的机器人；实体设备的软件放在第十七组。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 通知推送机器人 | 将监测/任务结果发到指定频道；交付推送程序与连接配置 | 发送端程序在本机/服务器，消息出现在聊天平台 | 由事件或定时任务触发；用户读通知 | 平台发消息 API 或支持的 webhook；不必调用模型；单向推送不等于能够读群消息 |
| 指令查询机器人 | 收到订单号等指令后查询并回复；交付事件处理和查询程序 | 聊天平台入口＋常开或托管后台 | 在会话中发命令，收到查询结果 | 平台事件/取消息接口、回复 API、数据库/业务连接；规则明确时无需模型 |
| 附件处理机器人 | 收表格、检查和整理、返回文件；交付消息、文件和处理程序 | 消息平台＋文件存储与处理后台 | 上传附件，收处理结果或错误反馈 | 平台文件下载/上传和消息接口、文件处理库；识别复杂非结构化资料时才按需加模型/OCR |
| 知识问答机器人 | 从指定资料回答提问并给出处；交付消息连接与检索问答系统 | 消息入口＋知识库和模型运行环境 | 发问题，查看回答与来源 | 平台接口、检索组件、模型；可能是固定 RAG 流程，也可能含 Agent，需说明 |
| 审批/登记机器人 | 通过表单、按钮登记任务或转交审批；交付交互与状态程序 | 消息卡片/会话＋后台记录 | 点按钮、补字段、查看处理状态 | 平台交互与身份接口、业务存储；规则工作流不必有模型；平台支持范围另核 |
| 网页/桌面 RPA 机器人 | 按步骤在界面中重复录入、下载或搬运；交付自动操作工程与样例 | 有浏览器/桌面的执行机器 | 启动任务或定时执行，检查日志 | 网页可用 Playwright 等、桌面另选对应控制工具；可无模型、无目标系统 API；登录和页面变化会影响运行 |

附件处理机器人可以有一个很直观的过程：在聊天窗口发来表格，程序下载附件，检查字段，把重复或缺失的记录列出来，再返回结果文件和处理说明。

这条流程如果规则固定，可以不调用模型。若它还会判断表格类型、选择处理办法，就可能结合上一组的 Agent。机器人提供消息入口，Agent 描述其中的任务执行方式，两者能组成同一件产品。

单向通知与双向交互也要分清。能向群里发报告，不代表已经能读群消息、接收附件或处理按钮点击；这些需要平台相应的接口与权限。[Telegram Bot API](https://core.telegram.org/bots/api)、[Slack 消息推送说明](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)

## 六、自动化与工作流

除了拿到这次的结果，还可以留下以后继续执行的办法。程序处理什么、从哪里启动、结果去哪里，都要具体。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 文件批处理程序 | 批量重命名、缩图、去重、转换；交付脚本/程序、配置和样例 | 本机文件夹与运行环境 | 选输入目录，运行，检查输出清单 | Python/Node.js；图片处理如 Pillow，音视频转换如 FFmpeg；通常无需外部 API |
| 数据清洗与导入流水线 | 按规则校验、清洗、写入目标表；交付步骤代码、字段映射和检查结果 | 本机或服务器，连接文件/数据库 | 放入新数据后执行，查看错误记录 | 如 Python/pandas、数据库驱动；外部系统接口按输入输出决定；模型非必需 |
| 定时报告流程 | 按时取数据、计算并生成报告；交付处理程序、触发配置和状态记录 | 常开电脑、服务器或托管调度平台 | 到时间启动，查看报告与失败状态 | 调度器＋处理工具；需要时连接数据和消息服务；仅有脚本不等于已定时运行 |
| 事件触发流程 | 新文件/表单/订单到达后处理；交付接收端、规则和动作 | 工作流平台或后台服务 | 事件到达后自动开始 | 文件监听或平台事件/webhook；可能无需模型；只在来源支持时采用事件推送 |
| 跨系统同步流程 | 将系统 A 数据按规则同步到 B；交付字段映射、去重与同步程序 | 本地服务/云工作流平台 | 定时或事件启动，核对同步结果 | 两端 API/连接器或导入导出路径；不是只交一个 HTTP 请求样例 |
| 可视化工作流工程 | 将多步处理做成可编辑节点图；交付平台内对象或可导入定义 | 指定工作流平台与其执行环境 | 导入，配置连接，运行并查看每步 | n8n 等候选；模型节点可选；平台配置/版本须说明，不是通用 JSON 即可跨平台运行 |
| 构建、测试与部署流程 | 提交代码后执行检查并生成安装包/部署；交付流程配置和运行证据 | 托管 CI 执行器或自建机器 | 提交代码或手动启动，查构建日志 | GitHub Actions 等候选、目标构建工具；不要求模型；部署目的地连接按需配置 |
| 设备/家居自动化 | 根据传感器、时间或状态控制设备；交付规则和设备连接配置 | Home Assistant 等中枢及已连接设备 | 事件触发，界面可查看和调整 | 中枢、兼容设备集成或协议；模型非必需；不是只交一段描述就已连接家中设备 |
| 模板化文件生成器 | 输入名单或业务数据，生成证书、标签、报价单等；交付模板与程序 | 本地窗口、命令行或网页 | 选择输入、填写选项、运行后取文件 | 文件生成工具和模板；规则填充无需模型；定时/事件启动另配 |

可以从一个证书生成器开始：确定版式，把姓名、活动名和日期设为替换字段，再让程序读取一份虚构名单，为每个人生成文件。更换名单，重新运行，就能得到下一批。

交付可以是一个简单窗口：选择名单、填活动名称、点击生成，结果进入指定文件夹。试用时看看长名字是否溢出、有没有漏文件。这样，读者能拿到本次证书，也能拿到下次继续使用的程序。

定时运行和收到文件后自动启动，需要另配触发机制与执行环境。n8n 的工作流可以导入导出，但定义文件要在相应平台中加载、配好连接后才会执行；写好程序或拿到工作流文件，不等于已配置好未来运行。[n8n 导入导出说明](https://docs.n8n.io/build/manage-workflows/export-and-import.md)

## 七、接口服务与软件复用

有些成果的使用者是另一个程序。它按约定提交数据，拿到查询、计算或处理结果；这样的服务也可以成为独立交付物。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 查询服务 | 商品号→库存/更新时间；交付查询程序、数据结构和接口说明 | 本机或服务器上的服务进程 | App/网页/机器人按约定请求数据 | 后端框架、数据库驱动；它自身提供 API，不必调用模型或第三方 API |
| 规则计算服务 | 重量/目的地→运费明细；交付计算规则、服务代码和样例 | 服务端，或本地提供接口的进程 | 其他程序传参数，接收计算结果 | Python/JavaScript 等与服务框架；模型非必需；外部费率连接按需 |
| 文件处理服务 | 上传文件→转换/提取结果；交付服务、任务处理和结果取回机制 | 后台进程与临时文件存储 | 上传后立即取结果，或按任务编号查询 | 文件处理工具；识别/生成模型按功能选择，格式转换本身不必用模型 |
| 业务操作服务 | 登记预约→记录编号/冲突原因；交付业务逻辑、存储和接口 | 应用后台＋数据库 | App/小程序提交数据并处理成功/失败返回 | 后端、数据库、权限机制；支付/短信等按需接入；不等于仅提供界面 |
| AI 处理服务 | 文字→标签/摘要等约定字段；交付模型连接、校验和服务 | 本机模型服务或服务器程序 | 其他程序提交输入、获取结构化结果 | 云端模型 API 或本地模型；标签与字段规则、失败返回需定义 |
| 事件接收服务 | 外部推送事件→确认接收并启动处理；交付接收端与重复事件处理 | 来源可到达的接收地址及后台 | 配置来源推送，观察事件处理结果 | Webhook/事件平台连接、自建服务；模型按需；接收地址不是模型 API |
| 客户端 SDK | 封装某服务的请求、认证和返回；交付软件包、文档与样例 | 调用者项目的依赖中 | 安装包后在代码里调用 | 目标语言工具链、对应服务；SDK 本身不替代服务及其账户 |
| 本地函数库/软件包 | 供其他程序复用的校验、计算或转换代码；交付包和调用说明 | 使用者的项目与运行环境 | 导入函数、传参、获取结果 | 相应语言与包管理器；可完全本地运行，不必提供网络 API |

例如做一个运费计算服务：网页或小程序把重量、目的地和运输方式传给它，它按约定规则返回运费明细。之后再增加一个查询机器人，也可以调用同一个服务，不必重写计算逻辑。

API 是约定的调用入口。接口说明、服务代码与已运行的服务，是不同交付状态；SDK 则是方便另一个程序调用服务的代码包。试做时先用几组示例输入调用，检查返回与错误说明，再考虑接入应用。[FastAPI 的服务与接口文档示例](https://fastapi.tiangolo.com/tutorial/first-steps/)

## 八、知识库、搜索与 AI 能力包

知识库可以从一批整理好的文件开始，也可以继续做成搜索、问答和可复用的工作能力。先看自己想怎样使用资料。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 整理好的资料库 | 按主题组织、有来源和目录的资料；交付文件与索引清单 | 本地文件夹、文档库或协作平台 | 浏览目录、打开资料 | 文件/文档工具；无需模型或外部 API；本身不含自动检索问答 |
| 可搜索知识站 | 将资料做成可浏览和关键词搜索的站点；交付站点、索引与更新方法 | 本地/在线网站 | 输入关键词，浏览匹配资料 | 静态搜索工具或搜索引擎；不必有模型；搜索部署方式另定 |
| 语义检索库/服务 | 按含义查相关片段；交付原文映射、索引、检索配置与接口 | 本地索引或检索服务器 | 程序/界面发查询，取得片段和来源 | 向量表示模型、索引工具；可本地或云端；不必有生成回答的大模型 |
| 带出处的资料问答系统 | 检索后由模型组织回答；交付资料处理、检索、模型连接和界面 | 平台应用或自建程序 | 提问，查看答案与支持片段 | 检索组件＋生成模型，向量/重排按设计采用；不等同“上传资料即微调模型” |
| Agent Skill 能力包 | 包含任务说明、脚本、参考和模板的复用包；交付目录结构与验证任务 | 支持该格式的 Agent 宿主 | 安装/放入指定位置，由宿主按规则使用 | 兼容宿主；包本身通常不运行模型；内部脚本需要什么依赖/API须逐项列出 |
| MCP 工具服务 | 把文件、业务查询或操作提供给兼容 AI 宿主；交付服务程序、工具定义和连接说明 | 本地进程或远程服务；用户入口在宿主中 | 宿主连接后发现并调用工具 | MCP SDK/兼容协议实现、宿主；服务未必用模型；底层业务 API 按工具确定；不是完整 Agent |
| 模型适配成果 | 针对任务训练的模型/适配器，附训练配置与评估 | 模型文件或托管模型服务 | 在匹配环境加载，或调用托管版本 | 训练/推理工具、算力、数据；与资料检索分开，具体路线需专项研究 |

一批读书笔记可以先整理成有来源的目录；加入关键词搜索，就能快速找到对应页面；再接检索和模型，可以尝试根据资料回答问题，并给出支持片段。每一步都可以单独成为有用的作品。检索问答会把找到的材料交给模型组织回答，并不自动意味着重新训练模型。[Dify 知识与检索说明](https://docs.dify.ai/en/cloud/use-dify/knowledge/readme)

Skill 可以保存一类任务的方法、脚本与模板，交给兼容的 Agent 宿主使用；MCP 服务可以把“查库存”“处理文件”等能力接给兼容应用。它们通常是助手会用到的能力，仍需写明安装或连接位置。[Agent Skills 格式](https://agentskills.io/home)、[MCP 架构](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture)

平台角色提示词与助手配置已列在第四组，这里不再重复增加一项。聊天问答机器人也可以连接本组的检索问答系统，它们分别说明入口与背后的能力。

## 九、数据、计算与可导入记录

清洗好的数据、会重算的工作簿、能再次运行的分析过程，也都是可以拿到并继续使用的成果。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 整洁数据集 | 去重、字段统一并保留来源的数据；交付 CSV/JSON 等、字段字典与处理说明 | 文件或数据存储中 | 导入表格、分析程序或业务系统 | 数据处理程序；源数据本地时无需外部 API；CSV 与 JSON 按结构选择，不各算一种用途 |
| 可查询数据库 | 有表关系、约束与查询的数据成果；交付数据库文件或建库/导入程序 | SQLite 文件，或数据库服务 | 查询、筛选、更新记录 | 数据库引擎与客户端；通常无需模型；数据库本身不含面向用户的完整界面 |
| 带公式工作簿 | 输入变化会重算的预算/排期模型；交付表、公式、图表和说明 | Excel 或兼容工作簿平台 | 改输入、看结果、检查公式 | 工作簿制作与计算工具；无需模型 API；外部数据连接另记 |
| 可复现分析笔记本 | 将文字、代码、数据和图表连在一起；交付笔记本、数据入口与环境 | Jupyter 等环境；浏览器为操作界面 | 按顺序运行单元，换数据重算 | Python/R 内核、计算库；API 按数据来源确定；静态导出版不能替代可运行笔记本 |
| 标注与评估数据 | 带标签、参考答案或评价规则的样本；交付数据、规则和质量说明 | 文件或标注/评估平台 | 导入训练/测试工具，或人工复核 | 标注工具与可选模型；人工/规则标注不必调用 API；评估程序另随需要提供 |
| 日历/联系人/书目记录 | 可导入目标工具的结构化条目；交付 ICS/VCF/BibTeX 等 | 文件及导入后的日历、通讯录或文献管理器 | 导入，检查时间、字段和重复项 | 格式生成工具；通常无需外部 API；文件导入与持续同步是两种交付 |
| 数据质量检查工具 | 检查缺失、重复、格式和范围；交付规则、程序与检查报告 | 本地或服务端 | 输入新数据，查看问题行与统计 | 数据处理/验证库；规则检查无需模型；这里交程序，D01 交已处理结果 |

同样是一份产品资料，可以先整理成行列记录；当每款产品还对应多条评价和多个来源时，也可以用有层次的结构保存关系，再转成工作簿、报告或页面。CSV、JSON 是按数据结构选择的载体，不必为了显得完整同时生成全部版本。

如果想亲自调假设，可以试一个预算工作簿：改人数、改场地费，看总支出怎样变化。若还想知道每一步分析怎样完成，则可以保留能运行的计算笔记本。[Jupyter 笔记本说明](https://jupyter-notebook.readthedocs.io/en/stable/notebook.html) 日程也不一定停在文字里，还可以导入日历，实际检查日期、时区和重复项。

## 十、文档、出版与教学材料

熟悉的文字工作也能打开新方向：做一本能放进阅读器的书、一份可填写表单，或一套打印后能玩的教具。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 文字底稿与研究报告 | 可修订论述、方案、说明；交付正文、引用与必要附件 | Markdown/文本、Word 或在线文档 | 阅读、修改、批注 | 文本编辑器、Word/LibreOffice Writer、按需 Pandoc；已有内容的编辑无需外部 API，写作时模型可由平台提供 |
| 固定版式出版物 | 正式报告、手册、海报或简历；交付 PDF 和按需源文件 | PDF 阅读器或印刷文件 | 阅读、打印，需修改时打开源工程 | 文档软件导出、LaTeX 或其他排版程序与字体；不必依赖模型 API；PDF 不自动可编辑或可印刷 |
| 可重排电子书 | 随屏幕调整的书籍；交付 EPUB、目录和素材 | 电子书阅读器 | 导入后阅读和导航 | 如 Pandoc 生成 EPUB，再做阅读器检查；通常无需外部 API；与固定分页 PDF 区分 |
| 可编辑演示稿 | 汇报、课程、路演；交付幻灯片、图表和讲者备注 | PowerPoint 或指定在线演示平台 | 放映、修改对象、按需导出 | PowerPoint、LibreOffice Impress 或程序生成工具；无需默认接模型 API；图片拼成的页面不能替代可编辑对象 |
| 可填写表单/问卷 | 收集字段与选择；交付 PDF 表单或在线表单及字段规则 | PDF 阅读器，或网页＋数据后台 | 填写后保存/提交 | PDF 表单工具或表单平台；在线存储/通知按需连接；空表模板与收集系统分开 |
| 课程练习与题库包 | 讲义、题目、答案和评分规则；交付文档/结构化题库及素材 | 文件、学习平台或应用 | 阅读、打印或导入学习系统 | 文档/题库工具；自动阅卷或平台接入按功能增加，不默认含 AI 导师 |
| 可打印教具/桌游材料 | 卡牌、棋盘、折纸或纸模型；交付印刷文件、规则和可编辑源 | 印刷文件与源工程，打印后成为纸面教具 | 打印、裁切、组装、按规则使用 | 矢量/排版工具；无需外部 API；尺寸与实物样张需检查 |

例如把一个系列的文章做成电子书：打开目录跳到某一章，调大字号，在阅读器里继续读。也可以做一套植物识别卡，正面放图，背面放名称与说明，打印后裁成卡片。

这些作品值得在打开或打印后看一遍。目录有没有跳对，长段落是否溢出，卡片正反面能否对齐，都属于作品本身。需要别人继续改的演示稿，则要保留文字和图表对象，不能只交一组页面截图。

## 十一、平面、信息表达和界面设计

设计成果可以是一张成图，也可以保留图层、路径、组件和交互关系，方便下一次继续改。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 位图图片/透明素材 | 插画、封面、产品概念图等；交付图像与必要来源/说明 | PNG/JPEG 等文件或素材平台 | 插入文章、网页和设计工程 | 图像生成模型或绘图工具；模型可由平台提供；图片成品使用时无需模型 API |
| 矢量图形/图标 | 可缩放、可改路径的标识素材；交付 SVG 等矢量源 | 矢量文件与设计软件 | 缩放、改色、编辑路径并导出 | 矢量编辑器或程序生成；无需外部 API；位图嵌入 SVG 不自动成为可编辑矢量 |
| 信息图/流程与关系图 | 把数据、步骤或关系画清楚；交付图和可编辑定义/源 | 图片、SVG、图表源或文档 | 阅读关系，更新数据或节点后再生成 | 图表库、Mermaid、矢量工具；API 按数据来源而定 |
| 可编辑设计稿 | 页面、海报或品牌应用设计；交付图层、文本、样式与素材 | 指定设计软件工程 | 修改文案、布局和视觉对象 | 设计软件及其脚本/插件；无需默认模型 API；具体文件兼容须验证 |
| 可点击界面原型 | 体现页面跳转和操作关系的模拟界面；交付原型工程/链接 | 原型工具或浏览器 | 点击体验流程、反馈设计 | 原型工具或网页代码；不必接业务 API；原型交互不证明后台功能已实现 |
| 设计系统与视觉组件库 | 可复用颜色、字体、设计组件与规则；交付变量、组件源和说明 | 指定设计软件库 | 引用、修改并复用视觉对象 | 设计工具；本身无需模型；程序组件见第三组 |

想做一组自己的图标，可以把交付要求写到“以后能改颜色、线条和形状”。需要的是可编辑路径时，就让 AI 说明生成和编辑方式，再打开文件选中对象试改，而不只看缩略图。

界面原型也适合第一次尝试：从首页点进详情，再点预约按钮，先体验流程是否顺畅。此时可以还没有真实订单和账户；原型中的跳转与实际业务系统分别确认。视觉组件放在本组，真正供代码项目导入的程序组件见第三组。

## 十二、音频、视频与动画

声音、视频和动画的交付，既可以是播放文件，也可以是一套能继续剪、继续调的制作工程。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 配音/播客音频 | 可播放的人声或节目；交付 WAV/MP3 及文稿 | 音频文件和播放平台 | 播放、发布或导入剪辑 | 录音、语音合成、音频编辑工具；云端或本地语音模型均可能，播放不需模型 |
| 多轨音频工程 | 可继续调整人声、音乐、音效的工程；交付工程、分轨与素材定位 | 指定音频工作站 | 改音量、剪辑、混音再导出 | 如 Audacity 或其他 DAW 与所用插件；外部 API 非必需；成品音频不是工程文件 |
| 剪辑成片 | 教程、宣传片、演示视频；交付视频及字幕等约定附件 | MP4 等文件或视频平台 | 播放和发布 | 剪辑工具、FFmpeg 或生成媒体工具；不必使用视频生成模型 |
| 可编辑视频工程 | 含镜头、时间线、转场和素材的制作项目 | 剪辑软件工程＋素材目录 | 打开项目修改镜头、字幕、配乐 | 对应剪辑软件及插件；素材随附；交付 MP4 不能代替工程 |
| 程序化动画/动态图解 | 按代码、数据生成动画；交付渲染结果和生成工程 | 动画运行环境及输出文件 | 修改参数/数据，再渲染 | 动画库、渲染工具；API 非必需；可播放 GIF 与可再生成程序分开 |
| 分镜、字幕与时间轴 | 辅助后续制作的结构化材料；交付分镜稿、SRT/VTT、镜头清单 | 文档/字幕文件与制作工程 | 导入剪辑、校时、按镜头制作 | 文档/字幕工具，转写模型按需；这些本身也是交付物，但不等于视频成片 |
| 音乐、音效与音乐事件文件 | 配乐、提示音或可由乐器播放的音符事件；交付音频，或 MIDI 加音源说明 | 音频文件/音乐工程，MIDI 在兼容软件中播放 | 直接播放，或选音源修改音符并导出 | 音乐制作/合成工具，生成模型按需；MIDI 不是录好的声音，听感依赖音源；不默认需要模型 API |
| 可编辑二维动画 | 带图层、关键帧或骨骼的动画；交付工程、素材与播放版 | 指定二维动画软件或运行环境 | 改动作、时间与图层后重新导出 | 对应动画工具及所用插件；外部 API 非必需；GIF/视频成品一般不保留这些编辑关系 |

想做一段“雨天散步”的声音作品，可以把旁白、雨声和音乐分开保留。觉得雨声太大，只调低这一轨；想换旁白，就替换对应片段，再导出播放版。

视频同理：成片拿来播放，工程拿来继续剪。字幕、素材位置和所用插件需要一起交接。MIDI 记录的是音符和演奏事件，听起来怎样还取决于音源；它与一段录好的声音有不同用法。[MIDI 官方说明](https://midi.org/about-midi-part-1overview)

## 十三、三维、空间与沉浸式成果

从一个自己熟悉的小物件开始，三维可以让人获得转动观察、摆放和修改空间对象的体验。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 三维模型资产 | 产品、场景部件或角色的几何/材质；交付 GLB/OBJ 等及必要贴图 | 模型文件，在兼容查看器/制作软件中打开 | 观察、导入其他工程或继续加工 | Blender 等建模工具或程序化生成；通常无需外部 API；格式转换和材质兼容需检查 |
| 可旋转三维展示 | 把模型做成可转动、缩放、换材质的体验；交付模型与展示程序 | 浏览器/应用；模型可本地或托管 | 拖动、缩放、切换展示选项 | 三维显示库/查看器＋模型；无需默认模型 API；它不是仅一张渲染图 |
| 可编辑空间场景 | 会场、房间或展陈的统一场景；交付对象、材质、灯光、相机工程 | 三维制作软件 | 换视角、移动对象、按尺寸改布局 | 如 Blender 等场景工具；需尺寸、空间数据与素材；查看版按用途导出 |
| 程序化/参数化场景模型 | 按输入生成几何或场景；交付脚本、节点或参数工程 | 相应建模环境 | 修改尺寸、数量等输入，再生成模型 | 建模工具的脚本/节点能力；通常无需外部 API；CAD 零件见下一组 |
| 角色绑定与三维动画 | 带骨骼、动作和场景的动画成果；交付工程、动作和渲染/模型 | 三维软件或兼容游戏引擎 | 播放、调整动作或导入互动项目 | 建模、绑定、动画和渲染工具；动作/模型服务按需；格式与骨骼适配需验证 |
| AR/VR 空间体验 | 在设备中查看、移动或操作虚拟对象；交付场景、应用工程和目标运行版本 | 支持的手机/头显/浏览器与设备运行环境 | 通过摄像头、头显或控制器体验 | 引擎/目标 XR SDK、兼容设备；外部模型 API 非必需；不能由三维模型文件推定已完成 AR/VR |

可以先试做一个桌面收纳架：上层放笔，下层有小抽屉，侧面留出耳机位置。先转到侧面看深度，再转到背面看开口。即使暂时不制作实物，也能试着用立体对象思考设计。

接着提出把上层加高，便要确认修改在哪里发生。展示页可能只支持旋转，真正改结构需要回到源工程；若希望输入数字就重新生成，应进一步要求参数或节点。建模工具与查看工具可以不同，模型交换文件也不一定保留完整的制作关系。[Blender glTF 文档](https://docs.blender.org/manual/en/3.6/addons/import_export/scene_gltf2.html)

会场布置也可研究同样的路径：在统一场景中移动桌椅、调整通道，再换视角观察。是否适合采用这条路线，要看需要的尺寸、修改与展示范围。

## 十四、工程设计与制造资料

如果希望继续按尺寸设计，或研究怎样制作实物，就可以认识 CAD、装配、切片和电路工程等更具体的成果。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 二维尺寸图 | 含比例、单位、尺寸和必要标注的平面/零件图；交付 CAD 源和阅读版 | CAD 软件与 PDF 等 | 测量、修改、讨论布局 | 二维 CAD/绘图工具；无需外部 API；探索性装修图不自动具备正式施工效力 |

延续收纳架的想法，如果想明确板材厚度、抽屉宽度和零件配合，就可以研究参数化 CAD。尺寸与约束保存在工程中，修改参数后重新计算，再检查结果。[FreeCAD 参数化说明](https://www.freecad.org/features.php?lang=lt)

希望继续打印或加工时，还要匹配材料、切片或刀路与具体设备。可以从一个简单零件或小样开始；漂亮的展示模型、可编辑工程和适合设备的生产资料，各自承担不同工作。装修的探索性布置图与正式施工成果，也应按实际用途区分。

## 十五、地图、数学与科学成果

地点可以摆到地图上，公式可以留下计算过程，实验可以形成可重新运行的分析或仿真。这些都可以从小范围尝试。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 交互点位地图 | 带筛选、弹窗或图层的地点展示；交付页面与空间数据 | 浏览器；底图可在线或本地 | 缩放、点地点、切图层 | 地图库、底图数据；在线底图/地理编码可能需服务与密钥，地图不一律需要模型 |
| 可编辑 GIS 工程 | 坐标、图层、空间分析和制图设置；交付工程与依赖数据 | QGIS 等 GIS 软件 | 打开工程、编辑图层、运行分析 | GIS 工具；数据服务按需；项目文件常引用外部数据，须一起交接 |
| 路线/区域分析工具 | 根据点位、路网与规则计算路径或覆盖；交付程序、数据与结果 | GIS/本地程序或网页服务 | 输入地点与约束，查看计算结果 | 路网与分析工具，地图/交通接口按需；静态示例不等于实时导航 |
| 数学推导与符号计算成果 | 公式推导、可重复计算和图表；交付源稿、代码与结果 | 文档编译或计算环境 | 阅读推导，改变量并重新计算 | LaTeX、符号/数值工具；一般无需外部 API；笔记本通用形式见第九组 |
| 仿真与实验分析工程 | 根据假设模拟系统或分析实验；交付模型、参数、代码和结果 | 对应仿真/计算软件 | 改条件、运行、比对结果 | 领域软件与算力；API 非必需；明确假设和验证范围，动画不证明物理仿真正确 |

一个小尝试是把自己收集的地点做成地图：点开某个点，看到备注、照片和来源；按类型筛选，观察它们怎样分布。交互页面、空间数据和可继续编辑的 GIS 工程可以按用途组合交付。

科学计算则可以从一个具体假设开始：改变初始条件，重跑计算，再看曲线怎样变化。此时要留下模型假设、参数和数据，不能只靠一段动画判断计算是否成立。计算笔记本的通用形式已在第九组解释，本组关注推导、空间分析和领域模型。

## 十六、游戏与互动内容

有些想法适合做成一件可以玩的东西。第一次不必搭建完整世界，一个动作、一条规则或一段分支故事也能形成作品。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 独立可玩游戏 | 有规则、输入与状态的游戏；交付源工程、素材和约定平台运行版 | 浏览器、桌面或手机 | 打开/安装后游玩 | 游戏引擎或网页代码、目标导出工具链；单机可无 API；联机/模型按需 |
| 平台内小游戏 | 在指定平台启动的游戏；交付平台适配工程与运行配置 | 指定小游戏宿主 | 从平台入口游玩 | 平台 SDK 与支持的引擎导出路线；不由普通网页游戏直接推定可发布；规则另核 |
| 互动叙事/分支课程 | 按选择推进剧情或学习路径；交付脚本、分支结构与运行作品 | 浏览器、阅读应用或互动引擎 | 作选择、查看对应内容 | 叙事工具/网页代码；预写分支无需模型，动态生成按需接入 |
| 关卡、模组与游戏资产 | 增加既有游戏的地图、角色或规则；交付兼容资产包与配置 | 指定游戏/编辑器 | 安装/导入后进入内容 | 宿主模组接口或编辑器；无需默认模型 API；不能脱离目标游戏声明可运行 |

第一次可以做一个只靠鼠标点击的小型解谜游戏：玩家点物品、查看提示，解开一个机关后结束。源工程留下后，再尝试更换谜题、调整反馈或增加一关。

分支故事也可以从几次选择开始。预先写好的选项与剧情可以按规则运行；想让角色临时生成对话，再研究模型接入。手机、网页和平台小游戏是运行入口，游戏规则和素材仍需针对目标环境检查。[Godot 工程导出说明](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)

## 十七、设备、传感器与实体机器人模块

如果感兴趣的是实体设备，需要说清交付的是固件、驱动、节点、控制模块还是仿真。软件文件、硬件设备与整机制造分别看待。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 单片机固件 | 读取按钮/传感器、控制灯或执行器；交付代码、固件和接线/烧录说明 | 指定板卡上 | 烧录后通电运行、读取串口记录 | 板卡工具链、驱动、兼容元件；云 API 非必需；必须明确板卡和引脚 |
| 设备驱动/通信程序 | 把串口、USB、网络设备接入软件；交付驱动/适配程序与协议配置 | 设备端或相连电脑 | 连接设备、配置端口、读写数据 | 设备 SDK/协议、驱动工具；不必用模型；模拟数据验证与实机连接分开 |
| 机器人传感器节点 | 读取/转换数据，向其他模块发布；交付软件包、消息和启动配置 | 机器人计算机或仿真环境 | 启动节点，查看数据和下游接收 | ROS 2 等框架、设备驱动；不必用模型 API；节点不是整台机器人 |
| 运动规划/控制模块 | 目标和状态→路径或控制指令；交付模块、机器人模型及测试材料 | 仿真器或指定机器人控制环境 | 仿真运行，再按明确条件做实机验证 | 规划/控制工具、设备接口；模型非必需；软件生成与机械动作验证分别记录 |
| 机器人仿真工程 | 可重复运行的机器人、场景和测试任务；交付模型、场景和启动配置 | 兼容仿真软件及计算机 | 启动场景、调整条件、记录结果 | 指定仿真器、插件和依赖；外部 API 非必需；仿真通过不等于实机通过 |

想接触硬件，可以先设想一个读取传感器并显示状态的小装置。需要确定板卡、传感器、通信方式和接线，再制作相应程序；没有设备时，也可以先做模拟输入或仿真，但要明确验证停在哪一步。

机器人里的采集节点、通信程序和运动模块可以分别交付。一个节点能读取和传递消息，不代表整机已经会导航或抓取；仿真场景能运行，也需要另外验证实机。ROS 2 的官方发布/订阅教程就是一个从小模块理解消息交互的入口。[ROS 2 节点示例](https://repo.test.ros2.org/en/rolling/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Publisher-And-Subscriber.html)

## 十八、复用、验证、修改与完整交接成果

成果拿到后能否继续改、再次运行或交给别人，往往取决于配套交付。这一组列的是跨前面各组的复用与交接材料。

| 具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| 可复用模板与素材库 | 报告、演示、设计等模板和复用资产；交付源文件、字段与样例 | 对应编辑软件或素材目录 | 替换内容、引用素材，再生成所需成品 | 兼容编辑工具；程序化生成见第六组 |
| 来源与复现材料 | 证据入口、处理步骤、数据版本和运行方法；交付来源清单、README 等 | 项目目录、文档或仓库 | 核对结论、按步骤复现 | 文档/版本管理工具；通常无需外部 API；复现所需数据和环境另注明 |
| 检查工具与验证报告 | 一套可重复检查的程序，或一次检查的证据；交付测试、日志和结果 | 项目/测试环境与报告文件 | 重跑检查，或查验已有记录 | 测试/渲染/计算工具；接口测试需目标服务；截图不能代替公式、业务或物理正确性检查 |
| 既有系统中的已保存修改 | 改好文档、更新库、修复应用；交付实际修改与可核对差异 | 用户指定的原系统/文件/仓库 | 在原位置继续使用 | 原应用工具、连接器/API或编辑工具；模型不一定是运行依赖；另存建议稿不等于已改原对象 |
| 完整工程/运行交接包 | 汇总源文件、依赖、配置示例和启动方式；交付仓库/目录/包及证据 | 仓库保存工程；程序在约定环境运行 | 获取工程、配环境、构建运行或接管服务 | Git、依赖管理与按需容器工具；运行服务需对应环境和连接配置 |

例如拿到一个文件生成器，能够点击运行固然重要；以后想换模板，还需要模板源文件、字段说明和一份可核对的样例。交给别人继续使用时，再说明依赖、输入输出和启动方式。

模板在这里集中列为复用资产，真正读取数据并生成文件的程序已列在第六组。另一种交付是原位置已经完成的修改：表格更新了、应用修好了、文档保存了。它不一定新增文件，但应有能确认修改生效的结果。

## 从清单里选一件真正想试的东西

可以留意自己在哪一行停了下来：是手机上的小应用，聊天里的机器人，能改尺寸的模型，还是属于自己的声音工程？

第一步可以先描述想拿到的东西和使用动作，让 AI 调查适合的方法。例如：

> 想试做一个桌面收纳架模型，上层放笔，下层有两个小抽屉。希望能换角度观察，后面还能改尺寸。请先研究适合的制作和查看方式，做一个简单版本，说明会交付哪些文件、怎样打开、需要哪些软件或接口。

也可以把目标放在熟悉的软件里：

> 想在浏览器里选中文字后保存摘录、网址和备注。先做一个只在指定页面生效的小扩展，能在本地查看并导出记录。请说明安装方法，以及以后增加摘要功能需要什么连接。

不需要先替 AI 选好所有工具，也不必一次做齐每一种版本。先有一个范围明确的小作品，实际打开、操作和修改，再决定是否继续。

转动那个模型，换一份名单，保存一张清单，或者给助手一个新问题。对下一件作品的想法，往往就从这些具体操作里出现。
