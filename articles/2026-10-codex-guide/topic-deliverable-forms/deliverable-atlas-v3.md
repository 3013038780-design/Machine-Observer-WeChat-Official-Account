# AI 协作交付物探索清单 v3

日期：2026-10-23。状态：供讨论和选材的资料目录，不是文章正文或已确认大纲。v1、v2 保留，新版作为当前入口。事实与来源边界见 [本轮研究记录](research/deliverable-paths-2026-10-23.md)。

## 阅读方法

本文邀请读者尝试没做过的成果：熟悉网站的人也可以尝试 App、小程序；熟悉报告的人也可以尝试计算器、知识库或任务助手。无需先证明原有形式不好。

这份目录按交付对象设置主要归属，组内逐项说明：**是什么与交付什么、载体在哪里、怎么用、需要什么工具或接口**。同一产品可以组合多个条目，例如“手机 App + 研究 Agent + 检索服务”。Agent 是任务执行方式，App 是应用形态，API 是连接方式，三者不能当作互斥选项。目录不是可相加的行业分类，也不宣称穷尽所有职业用途。

“载体”同时看两处：用户在哪里接触成品，以及支撑程序在哪里运行。例如网页在浏览器里显示，后台可能运行在服务器上；源代码在仓库中，并不能回答程序在哪里运行。

“工具/API”栏是典型路线及条件，不是全部必选软件，也不是本会话已验证的能力列表。表内列出的具体任务均为说明性例子，未实际制作。

### 接口口径

- **外部模型接口**：向云端模型服务发请求。现有平台可能代为提供，使用者不一定另配密钥。
- **本地模型接口**：程序通过本地服务或推理库调用模型；“不用云端模型 API”不等于“没有软件接口”。
- **业务/平台接口**：订单、地图、消息、存储等系统提供的连接。机器人通常需要消息平台连接，但不一定需要模型。
- **宿主接口**：浏览器、办公软件、设计软件或操作系统提供的扩展能力，不等于付费云端 API。
- **无需外部 API**：成品的基础用法可在本地完成，不表示制作过程中未用 AI、程序内部没有接口或任何扩展功能都可离线。

### 交付状态

各项均应按任务注明交到哪一步：方案/设计、可编辑源文件、可运行成品、已连接/部署的系统。制作工具与使用工具可以不同；使用成品通常不需要重新调用制作阶段使用的模型。静态成果记录打开、编辑与导出情况；运行成果记录样例输入、结果、错误反馈与启动方式。

## 四、Agent：按任务执行方式与实际载体展开

本目录采用工作定义：模型参与选择下一步和工具，系统执行并读取反馈，围绕目标继续推进。固定步骤中的一次模型调用不自动构成这种 Agent；现有平台里“角色助手”也常被宽泛称为 Agent，因此单列辨析项。定义存在行业用法差异。[Anthropic 对工作流和 Agent 的区分](https://www.anthropic.com/research/building-effective-agents)

这里有两个独立维度：研究、编程等是职责；平台、本地、服务端是运行位置。下列是具名组合示例，不能相加当作互斥类别数量。Agent 不要求全天运行、不要求多个代理，也不要求具有人格或实体外形。

| 编号／具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| G01 平台内任务 Agent | 在现有平台中调用工具推进任务；交付角色/目标配置、工具连接与样例 | 平台的运行服务；用户从平台界面进入 | 选助手、给任务、查看过程或回答追问 | 平台须支持相应工具与执行机制；模型可由平台供给；业务工具需连接；未必需用户另配模型密钥 |
| G02 本地资料研究 Agent | 检索材料、补查缺口、保存来源并形成结果；交付程序、工具与运行配置 | 本机进程＋终端/本地页面 | 指定问题和资料范围，运行后审阅报告与来源 | Python/JavaScript 等运行时；云端模型 API 或合适的本地模型；网络研究需搜索/浏览连接，本地研究可只读文件 |
| G03 编程 Agent | 读项目、改代码、运行检查并根据反馈继续；交付专用执行程序或宿主配置及验证例子 | 本地工程环境或隔离的云端执行环境 | 给出改动目标，审阅代码差异和测试结果 | 模型、文件/终端/测试工具；仓库托管接口按需求接入；交付“用 Agent 改好的代码”与“Agent 系统”是两项不同成果 |
| G04 数据分析 Agent | 判断分析步骤，调用计算工具并检查结果；交付分析程序及受控数据连接 | 本机分析环境或服务器，配聊天/任务界面 | 提交问题和数据，查看分析过程、图表和可复现文件 | 模型、本地计算库/SQL 工具；数据库连接按需；不能只交一份报告就称已交付 Agent |
| G05 浏览器操作 Agent | 根据页面反馈选择点击、输入或导航；交付执行程序、浏览工具和任务配置 | 有浏览器的电脑/服务器；任务入口可为网页 | 给目标，在关键节点确认或接管 | 模型＋浏览器控制/观察工具；可走网页界面，不一定有目标网站 API；需可用登录与访问条件 |
| G06 工单处理 Agent | 判断工单，检索政策、查询业务并起草/执行动作；交付应用与工具连接 | 服务端＋客服工作台/消息入口 | 新工单触发，或人工指派；检查处理记录 | 模型、工单/订单等业务接口或连接器、权限与审计；对外动作范围要明确 |
| G07 桌面操作 Agent | 通过屏幕、控件和应用工具推进本机任务；交付操作程序与任务配置 | 获准访问应用的桌面运行环境 | 给任务、观察执行，需要时接管 | 模型、截图/无障碍/应用控制工具；不要求每个应用均有网络 API；不能只交提示词 |
| G08 持续任务 Agent 服务 | 接收任务、排队执行、暂停/恢复并记录状态；交付服务工程与运行配置 | 服务器或常开的本机；网页/API 为入口 | 提交任务后查看状态、补充信息、取结果 | 模型连接、执行器、状态存储；队列/调度按规模选择；模型本身不会承担持久运行 |
| G09 多 Agent 协作系统 | 多个职责单元协作，统一分配任务和汇总；交付编排程序与各角色配置 | 本地或服务端进程，入口按产品设计 | 提交一个任务，查看分工、结果及汇总 | 模型、通信/编排逻辑、共享状态及工具；框架可选；多个提示词文件本身不等于运行中的协作系统 |
| G10 专用角色助手（宽泛称 Agent） | 通过固定角色和资料回答问题；交付提示词/平台配置/知识资料 | 现有对话平台或自建聊天应用 | 对话提问、取得回答 | 平台模型或自行连接模型；若无自主工具执行，不按上述严格定义归为任务 Agent，仍是有效交付物 |

### Agent 最小交付说明

至少明确：任务与结束条件；模型来自哪里；工具能读/改什么；入口与执行位置；状态和文件保存在哪里；何时交回人判断；一个实际运行例子。配置文件可由现有平台执行，但单独一份配置不等于平台、模型或运行资源一并交付。

## 五、机器人：消息入口、自动操作和实体设备分别写

“机器人”常描述入口或自动执行角色，不必具有 AI 能力。消息机器人可以内部调用 Agent，Agent 也可以采用消息机器人作为入口。消息接收、回复和简单推送的接口范围并不相同。[Telegram Bot API](https://core.telegram.org/bots/api)、[Slack incoming webhook](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)

| 编号／具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |
| --- | --- | --- | --- | --- |
| B01 通知推送机器人 | 将监测/任务结果发到指定频道；交付推送程序与连接配置 | 发送端程序在本机/服务器，消息出现在聊天平台 | 由事件或定时任务触发；用户读通知 | 平台发消息 API 或支持的 webhook；不必调用模型；单向推送不等于能够读群消息 |
| B02 指令查询机器人 | 收到订单号等指令后查询并回复；交付事件处理和查询程序 | 聊天平台入口＋常开或托管后台 | 在会话中发命令，收到查询结果 | 平台事件/取消息接口、回复 API、数据库/业务连接；规则明确时无需模型 |
| B03 附件处理机器人 | 收表格、检查和整理、返回文件；交付消息、文件和处理程序 | 消息平台＋文件存储与处理后台 | 上传附件，收处理结果或错误反馈 | 平台文件下载/上传和消息接口、文件处理库；识别复杂非结构化资料时才按需加模型/OCR |
| B04 知识问答机器人 | 从指定资料回答提问并给出处；交付消息连接与检索问答系统 | 消息入口＋知识库和模型运行环境 | 发问题，查看回答与来源 | 平台接口、检索组件、模型；可能是固定 RAG 流程，也可能含 Agent，需说明 |
| B05 审批/登记机器人 | 通过表单、按钮登记任务或转交审批；交付交互与状态程序 | 消息卡片/会话＋后台记录 | 点按钮、补字段、查看处理状态 | 平台交互与身份接口、业务存储；规则工作流不必有模型；平台支持范围另核 |
| B06 网页/桌面 RPA 机器人 | 按步骤在界面中重复录入、下载或搬运；交付自动操作工程与样例 | 有浏览器/桌面的执行机器 | 启动任务或定时执行，检查日志 | 网页可用 Playwright 等、桌面另选对应控制工具；可无模型、无目标系统 API；登录和页面变化会影响运行 |
| B07 实体机器人软件 | 读取传感器、通信、规划或控制；交付指定模块，详见第十七组 | 板卡、机器人计算机或仿真环境 | 接入兼容硬件或先运行仿真 | 设备 SDK/驱动、ROS 2 等候选；型号、协议和验证范围必须确定；软件交付不包含整机制造 |

## 六、自动化与工作流

工作流连接多个步骤；执行载体可以是脚本运行环境、工作流平台或自动化服务器。导出的定义文件需要导入兼容环境并配好连接才能运行。[n8n 工作流说明](https://docs.n8n.io/workflows/)

| 编号／具体成果 | 是什么、交付什么 | 载体在哪里 | 怎么用 | 制作工具与 API 条件 |

## 十九、除 Agent、机器人外，优先解释的通用名称

以下是编辑判断，不是普及率排名。选择依据是用途跨领域、公众常听到且容易误认交付范围。

| 名称 | 最容易省略的内容 | 应落到的具体说明 |
| --- | --- | --- |
| 工作流/自动化 | 是步骤图、可导入工程，还是已运行服务？ | 输入、步骤、触发器、执行位置、输出和失败记录 |
| 知识库 | 是文档集合、搜索，还是 AI 问答？ | 原资料、索引、检索、模型与用户入口分别是什么 |
| 插件/扩展 | 装到哪个软件？能调用什么？ | 宿主、安装包、运行权限、后台和依赖 |
| API 服务 | 是接口设计、服务代码，还是可调用地址？ | 输入输出、运行位置、调用方式、访问条件与错误处理 |
| 助手/智能应用 | 是角色配置、聊天界面，还是能执行任务？ | 模型、工具、执行程序、载体与完成边界 |
| 看板/仪表盘 | 是图片、静态数据页，还是持续更新？ | 数据来源、更新时间、筛选能力和后台 |
| 数据库 | 是一份表、数据库文件，还是有界面的系统？ | 数据结构、查询方式、服务位置和管理入口 |
| 小工具/小程序 | “小”不说明技术和运行环境；口语小程序不一定是平台小程序 | 本地脚本、网页工具、桌面应用或指定平台项目 |
| 模型/原型/仿真 | 同名可能是 AI 权重、三维几何、设计样机或计算模型 | 指明对象、可执行/可编辑范围及验证阶段 |
| 平台/系统 | 用宽泛名字暗示已包含多个子系统 | 用户入口、后台、数据、权限和具体功能分别交付到哪里 |

## 二十、后续写作取舍

研究清单负责覆盖，正文仍需一条读者容易跟随的主线。Agent、机器人是需要解释清楚的代表性成果，不能因为本轮讨论较多就把整篇改成 Agent 教程。建议保留三条探索跨度：已有熟悉成果的新入口（网站→App/小程序）；从看内容到运行任务（报告→工具/流程/Agent）；进入陌生制作领域（三维/CAD/声音等）。箭头表示探索路径，不代表优劣或必须升级顺序。

本轮不制作实际产品、不安装软件、不配置外部服务或自动化、不生成文章 HTML。尚未提交正式详细大纲；目录审核与文章大纲审核分别进行。
