# 让 AI 帮你做点以前没做过的东西

标题候选｜纯文字稿 v1，待审阅｜2026-10-23

会让 AI 写文章、做图片，也许已经做过自己的网页。下一次，还想试点什么？

可以是一个装在手机里的打包清单，一张能筛选地点的地图，一个能转到背面看的收纳架模型。也可以是一套换了名单就能重新生成证书的程序，或者一个收到问题后会查资料、补查来源的研究助手。

这些成果里，有些可以直接阅读，有些需要安装，有些依附现有软件，还有些需要程序和模型一起运行。知道它们具体长什么样，才容易想到：“这个可以试试。”

下面按使用方式把它们放在几组表里。它们可以组合：一个手机 App 可以连接研究 Agent，研究结果也可以做成报告、表格或可操作页面。分组只是方便寻找，不是必须依次完成的进阶路线。

文中的小作品是帮助理解的设计示例；具体制作需要结合当前工具、平台和设备确定。表里的“无需外部 API”，指所描述的基础用法可以在本地完成。制作时用了 AI，不代表成品每次使用都需要调用模型。

## 一、先做一件可以阅读、查阅和动手操作的作品

一份整理好的资料，可以有很多种去处。它可以成为电子书，也可以成为有搜索入口的知识站；可以变成带公式的工作簿，也可以变成调几个参数就会重新计算的小工具。

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 可编辑文档 | 报告、方案、操作手册，保留批注与修改能力 | 在 Word、LibreOffice 或在线文档中继续编辑 | 对应文档工具；本地编辑无需外部 API |
| 固定版式出版物 | 有分页和目录的手册、作品集、可打印教具 | 打开 PDF 阅读或打印；修改时使用源文件 | 文档或排版工具、字体；基础用法无需外部 API |
| 电子书 | 把系列文章、课程材料整理成能跳转章节的书 | 将 EPUB 导入阅读器，调整字号、浏览目录 | 如 Pandoc 等制作工具及阅读器 |
| 可编辑演示稿 | 课程、汇报、路演，保留文字和图表对象 | 在演示软件中修改、放映 | PowerPoint、Impress 等；使用时不必调用模型 |
| 带公式工作簿 | 预算、排期、报价，修改输入后重新计算 | 在 Excel 或兼容平台中改数据、看结果 | 工作簿工具与公式计算；实时取数时另接数据源 |
| 交互报告、数据看板 | 筛选产品、查看趋势、点开来源或明细 | 在浏览器或看板平台中操作 | 网页/图表工具；静态数据可随附，持续更新需数据连接 |
| 计算器、模拟器 | 调整人数、价格或假设，观察结果变化 | 在网页或本地程序中输入和计算 | 计算规则与程序；规则明确时无需模型 |
| 数据集与数据库 | 可导入的产品目录，或能按条件查询的记录库 | 导入分析工具，或通过数据库客户端/界面查询 | CSV/JSON 等数据文件；SQLite 等数据库工具；模型非必需 |
| 可复现计算笔记本 | 将说明、计算步骤、数据和图表放在一起 | 在 Jupyter 等环境中运行，换数据重算 | 对应计算内核与依赖；外部数据按需连接 |
| 可搜索知识站 | 给读书笔记、项目资料或课程内容增加目录与搜索 | 浏览器里搜关键词，打开对应资料 | 网站与搜索索引；关键词搜索不必调用模型 |
| 交互地图、地理工程 | 展示探店地点、采样点或展览路线；继续编辑图层 | 浏览器中点选，或在 GIS 软件中编辑 | 地图库或 QGIS；在线底图、地理编码可能需要服务接口 |
| 可导入记录 | 整理一学期日程、通讯录或参考书目 | 把日历、联系人或书目文件导入目标工具 | ICS、VCF、BibTeX 等格式及兼容软件；导入不等于持续同步 |

例如，准备一次小型活动，可以先做一个预算工作簿：人数、场地费、餐费是输入，预计总支出和人均费用由公式计算。后来人数从二十人改成三十人，就改输入，让同一份文件继续算。

也可以把这套规则做成网页计算器。打开页面，拖动人数，选择是否含餐，看总价如何变化。工作簿适合继续检查和修改公式，网页可以把操作入口做得更直观。两种作品各有值得尝试的地方。

知识站则提供另一种体验。把一批笔记整理好，输入一个关键词，就能找到相关页面；打开条目，还能回到原始材料。如果进一步接上检索和模型，也可以做成“根据这些资料回答问题，并列出出处”的问答工具。

这里的“知识库”需要说具体：资料集合、可搜索站点和 AI 问答系统，分别包含不同东西。检索问答会先找相关片段，再把片段交给模型组织回答；它并不自动意味着重新训练了一个模型。[Dify 的知识与检索说明](https://docs.dify.ai/en/cloud/use-dify/knowledge/readme)

### 还可以把作品做成声音、画面和可编辑工程

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 图片、矢量图与信息图 | 封面、透明素材、可缩放图标、流程和关系图 | 插入文章或网页；在设计工具中修改源文件 | 绘图/矢量工具或生成模型；用成品时不必再次调用模型 |
| 可编辑设计稿、点击原型 | 修改图层与文案，或点击体验应用流程 | 在指定设计工具或浏览器中打开 | 设计/原型工具；可点击原型未必连接真实业务 |
| 配音、播客、音效 | 把讲解做成声音，给作品加提示音 | 播放音频，或导入后续制作 | 录音、语音合成、音频编辑工具；模型可由平台提供或本地运行 |
| 多轨音频工程 | 分别调整旁白、音乐和环境声 | 在 Audacity 等音频编辑软件中修改后导出 | 对应工程、各条音轨及所用素材 |
| 视频、二维动画 | 教程、动态图解、互动作品的展示片 | 播放成片，或回到剪辑/动画软件修改 | 剪辑/动画工具、FFmpeg 等；不必全部依靠视频生成模型 |
| 字幕、分镜与时间轴 | 为下一步拍摄、配音和剪辑准备材料 | 阅读镜头清单，或导入字幕与剪辑工具 | 字幕/文档工具；转写与生成能力按任务选择 |

假设想做一段“雨天散步”的声音作品，可以保留旁白、雨声和音乐三条音轨。觉得雨声太大，就只调低雨声；想换一段旁白，就替换对应片段，再导出新的音频。

拿到可播放文件，和拿到这套能继续修改的工程，是两种交付。视频、演示稿、设计稿也有类似区别。第一次尝试时，除了说想要什么效果，还可以补一句：希望以后能改哪一部分。

## 二、做一个自己能打开、安装或加入常用软件的小工具

有些作品会在生活里留下一个固定入口：手机上的图标、浏览器里的按钮、电脑菜单栏的小工具。

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 网站、网页应用 | 作品展示、活动报名、清单管理 | 浏览器打开链接；保存业务记录时通常需要存储 | HTML/CSS/JavaScript 或网页框架；后台按功能增加 |
| 可安装网页应用 PWA | 给网页增加安装入口，按设计支持部分离线使用 | 在支持的平台安装或添加入口后打开 | 网页工程、安装配置与按需缓存；体验因平台而异 |
| iPhone/iPad App | 随手记录、拍照归档、个人小工具 | 安装到设备，触控使用 | Xcode、平台 SDK、相应签名与分发条件；云服务按需 |
| Android App | 计时、清单、设备数据展示 | 安装到 Android 设备 | Android SDK 与构建工具；离线功能无需外部模型 API |
| 微信或其他平台小程序 | 预约、查询、活动互动 | 在对应平台中搜索、扫码或通过入口打开 | 对应开发工具、平台接口与发布条件；不同平台分别适配 |
| 桌面应用、菜单栏工具 | 批量改文件、计时、快速记录 | 在电脑窗口或菜单栏/托盘中操作 | 原生工具链，或 Electron、Tauri 等；本地任务可无外部 API |
| 浏览器扩展 | 摘录文章、整理标签页、给页面加按钮 | 安装后，从扩展栏或网页中使用 | 浏览器扩展接口与相应权限；是否接模型取决于功能 |
| 办公、编辑器或设计软件插件 | 在原软件里批量检查、排版、生成对象 | 从宿主软件的菜单、命令或侧栏进入 | 指定宿主的插件/脚本接口；不能将一种插件通用于全部软件 |
| 命令行工具、系统快捷操作 | 输入命令处理文件，或点快捷指令完成一组动作 | 终端、系统快捷指令或右键菜单 | 对应运行环境和系统能力；外部接口按功能决定 |
| 游戏、互动叙事与关卡 | 解谜小游戏、分支故事、既有游戏的新关卡 | 浏览器、手机、电脑或指定游戏中 | 网页代码、游戏引擎或宿主编辑器；单机玩法可无模型 |

可以从一份自己的出行打包清单开始。

新建“周末露营”，加入帐篷、头灯和雨衣；已经放进包里的物品点一下勾选。第二次出行时，复制清单，删去不需要的东西，再继续用。

如果把它做成网页，就从浏览器打开；做成手机 App，就有设备上的应用入口；做成微信小程序，就在微信里进入。第一次选一种就够了。保存到本机、与朋友共享、跨设备同步，是可以逐步增加的功能。

这里有一个容易忽略的事实：AI 可以协助写程序，而程序生成后，添加物品、勾选和保存可以按既定规则运行。只有要加入“根据目的地推荐装备”等模型功能时，才需要另行设计相应模型连接。

小程序也有自己的工程与运行环境。微信官方示例同时提供小程序代码、平台 API 与云开发示例，不能把一份普通网页当作已经完成了小程序适配。[微信小程序官方示例](https://github.com/wechat-miniprogram/miniprogram-demo)

插件的想象空间则藏在熟悉的软件里。阅读网页时，希望选中文字后能保存摘录、网址和自己的备注，可以尝试做一个浏览器扩展。按钮就在阅读发生的地方，保存的内容可以留在本地，也可以按需要同步到其他系统。

要增加自动摘要，再接模型；只保存原文和备注，则可以不调用模型。Chrome 官方教程就展示了通过扩展读取页面、增加阅读时间提示的做法，说明网页里的小功能本身也可以成为独立作品。[Chrome 扩展教程](https://developer.chrome.com/docs/extensions/get-started/tutorial/scripts-on-every-tab)

### 有些工具，是给其他程序使用的

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 可调用的接口服务 | 输入重量、目的地，返回运费；或输入商品编号，返回库存 | 在本机或服务器运行，由 App、网页等发请求 | 服务程序、规则或数据库；它自身提供 API，未必需要外部模型 |
| 本地软件库、组件、SDK | 让其他项目复用计算、界面，或调用某个服务 | 安装到使用者项目，在代码中调用 | 对应语言/框架与依赖；SDK 不替代它所连接的服务 |

API 可以理解为软件之间约定好的调用入口。运费计算服务收到重量和目的地，检查输入，再返回运费明细。之后，无论前面接网页、小程序还是聊天机器人，都可以调用同一套计算规则。

这时需要说明交付到哪一步：只有接口说明，还是有能运行的服务程序？服务是否已经启动，调用者能从哪里访问？FastAPI 官方入门示例分别展示了运行服务、返回数据与生成接口文档，这些是相关但不同的东西。[FastAPI 入门](https://fastapi.tiangolo.com/tutorial/first-steps/)

## 三、试着做一个能换角度看、能继续修改的空间对象

如果从未做过三维或 CAD，可以先选一个很小、很熟悉的对象：桌面收纳架、书架上的分隔板，或者房间里的一角。

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 三维模型与可旋转展示 | 从不同方向看产品、家具或角色 | 在兼容查看器、浏览器或应用里转动、缩放 | 建模工具和展示程序；通常不要求外部模型 API |
| 可编辑空间场景 | 调整会场座位、展陈或房间物件的位置 | 在三维软件中移动对象、换相机视角 | Blender 等场景工具及实际尺寸、素材；展示文件另按用途导出 |
| 参数化模型 | 输入宽、高、厚度后重新生成形状 | 在 CAD/建模工程中改参数，再计算 | 如 FreeCAD 等参数化工具或生成脚本 |
| 二维尺寸图 | 说明家具、平面布置或零件的尺寸关系 | 在 CAD 中修改，导出阅读版查看 | CAD 工具、单位和尺寸依据 |
| 零件与装配工程 | 设计分开的部件及相互位置 | 在兼容 CAD 中查看、修改和检查配合 | 参数化/装配工具；需交付零件及其关系 |
| 打印、切割与加工资料 | 为三维打印、激光切割等准备模型或图纸 | 导入切片/CAM 软件，匹配具体设备 | 建模/CAD、切片或 CAM 工具；机器参数需另确认 |
| 三维动画与沉浸式场景 | 让角色运动，或进入可体验的虚拟空间 | 动画软件、引擎、兼容手机/头显 | 动画工程、引擎、目标设备 SDK 与设备 |
| 电路工程、设备仿真 | 画原理图和电路板，或模拟设备运行 | 在电子设计/仿真软件中检查和运行 | 如 KiCad 或指定仿真器；需要相应元件、模型和参数 |

设想做一个桌面收纳架：上层放笔，下层放零散配件，侧面留出耳机位置。

第一次可以先要一个能转动的模型。转到侧面看深度，转到背面看开口，拉近观察抽屉和隔板的位置。即使暂时不制作实物，也能获得一种过去没用过的观察体验。

接着想把上层加高、抽屉缩窄，就要确认修改发生在哪里。展示页可能只提供旋转；真正改变形状，需要回到建模工程。如果希望输入几个数字就重新生成，则可以研究参数化建模。FreeCAD 官方将参数和对象关系作为改变形状的基础，这与单纯查看一份模型不同。[FreeCAD 功能说明](https://www.freecad.org/features.php?lang=lt)

制作工具和最终查看工具也可以不同。三维软件里完成场景，再导出适合展示的模型供浏览器或应用使用，是一种交付路径。Blender 的 glTF 文档说明了这种模型交换用途，也记录了可保留内容与转换限制；展示文件不应被当作完整源工程的替身。[Blender glTF 文档](https://docs.blender.org/manual/en/3.6/addons/import_export/scene_gltf2.html)

会场或房间布局也是相近的探索：在一个统一场景中移动桌椅，换几个角度观察。需要实际制作时，再进一步核对尺寸、材料、装配或工艺；一个好看的模型并不自动完成这些工作。

## 四、给下次的工作留一个能重新运行的办法

有些交付物的乐趣，在于第二次打开时，它还能继续工作。

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 模板与生成器 | 输入名单生成证书，输入项目数据生成报价单 | 编辑模板，或在程序中选择输入、执行生成 | 模板、字段规则、文件生成工具；规则填充不必调用模型 |
| 文件批处理程序 | 一批照片缩图、重命名、分类或转换 | 在本机选择目录，运行并查看输出 | Python/Node.js、Pillow、FFmpeg 等对应工具 |
| 数据清洗导入流程 | 校验字段、去重，写入目标表或数据库 | 放入新数据后启动，检查问题记录 | 如 pandas、数据库驱动；外部数据源按需连接 |
| 定时报告、变更监测 | 周期性汇总数据，或发现变化后通知 | 在常开电脑、服务器或托管调度平台执行 | 处理程序、触发机制、数据连接与按需通知接口 |
| 事件处理、跨系统同步 | 新订单到来后登记，将记录同步到另一系统 | 事件触发或定期运行，查看处理结果 | 两端接口/连接器，或兼容导入导出路径 |
| 可视化工作流工程 | 将取数、处理、生成、通知连接成可编辑步骤 | 导入指定工作流平台，配好连接后运行 | 如 n8n 及其执行环境；模型节点按需加入 |
| 构建检查、设备自动化 | 提交代码后检查和打包，或让设备按条件动作 | CI 执行环境、设备中枢与相连设备 | 对应构建工具或设备集成；模型不是必选条件 |

例如，一次活动需要给参与者制作证书。

先确定版式，把姓名、活动名和日期设为可替换字段。然后准备名单，让程序读取每一行，生成对应文件，放进输出文件夹。换一份虚构名单试运行，就能检查名字有没有错位、长名字会不会溢出、文件是否漏了。

如果只留下证书文件，拿到的是本次成果。再留下模板、生成程序和操作入口，下次就能换名单继续做。这个入口可以是一个窗口：选名单、填活动名、点击生成。用户不必每次都去修改代码。

如果还想让它在收到报名表后自动运行，需要增加新的触发方式，并确定程序在哪里持续等待、结果存在哪里、失败怎样被发现。文件处理程序、自动启动配置和已经验证的流程，是不同的完成状态。

可视化工作流也一样。n8n 可以导出、导入工作流 JSON，但文件要在相应环境中加载，并配好所需连接才能执行。拿到定义文件，和接管一个已经运行的流程，并不是同一份交付。[n8n 导入导出说明](https://docs.n8n.io/build/manage-workflows/export-and-import.md)

## 五、Agent、机器人和助手，具体会交付成什么

这些名称要落到程序和入口上，才容易理解。下面列的是具体组合：研究是任务，本地或服务器是运行位置，聊天窗口是入口，它们可以组合在同一件作品里。

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| 平台里的专用角色助手 | 按固定角色和资料回答问题、协助写作 | 在原平台选择助手后对话 | 平台提供的模型、配置与资料；可能无需另配模型密钥 |
| 平台里的任务 Agent | 围绕目标选择工具，按反馈继续处理 | 在支持该能力的平台发任务、看过程 | 平台的执行机制、模型与工具连接 |
| 本地/服务端研究 Agent | 读资料、搜索、补查、记录来源并整理结果 | 从终端、网页或应用提交任务；程序在电脑或服务器运行 | 模型、检索/浏览工具、文件与状态存储 |
| 编程、数据分析 Agent | 修改项目并检查，或按问题调用计算工具分析 | 在工程/分析环境中交任务，审阅差异和结果 | 模型、文件/终端/测试或计算工具；业务数据按需连接 |
| 通知推送机器人 | 将报告、异常或变化通知发到指定会话 | 程序发消息，用户在消息平台阅读 | 平台发消息接口或支持的 webhook；无需默认接模型 |
| 指令查询、登记机器人 | 收到编号查状态，或通过按钮登记和审批 | 在聊天平台输入指令、填字段、点按钮 | 消息接收/回复接口、业务查询与存储；可按规则运行 |
| 附件处理、问答机器人 | 收表格返回处理结果，或根据资料回答问题 | 在聊天窗口发文件或问题 | 平台文件/消息连接；文件处理库，或检索与模型 |
| 网页/桌面操作程序 | 在界面中填写、下载、搬运；也可由模型参与选择动作 | 在有浏览器或桌面的机器上运行 | 自动化/应用控制工具；固定步骤可无模型，Agent 方式需模型参与 |
| 实体机器人软件模块 | 采集传感器、传递消息、规划或控制运动 | 指定板卡、机器人计算机或仿真器 | 设备驱动/协议、ROS 2 等工具；不必使用大模型，须明确硬件与验证范围 |

以资料研究为例，可以设计一个这样的助手：接收问题和资料范围，先找相关材料；发现某个关键数字缺来源，就继续检索；资料足够后形成结果，并附上对应出处。

当模型参与判断下一步查什么、用哪个工具，以及如何根据返回结果继续推进时，就接近这里讨论的任务 Agent。Anthropic 用模型是否动态主导过程和工具使用，区分 Agent 与主要由预设代码安排步骤的工作流。实际产品也可以把两种方式组合起来。[Agent 与工作流的区分](https://www.anthropic.com/research/building-effective-agents)

这个研究助手可以是电脑上的一个程序：打开本地页面，输入问题，等它把资料和报告保存到约定位置。也可以部署成服务，让人从网页提交任务。入口看起来简单，后面仍然需要执行程序、模型、检索工具和存储。

如果把它接到消息平台，就能在聊天里发问题、收结果。这里，机器人提供消息入口，Agent 负责需要判断的任务过程。一个只按订单号查询状态的机器人，则可以由固定规则完成，不必调用模型。

模型来自哪里，也要说清。在现有平台里，模型可能由平台提供；自建程序可以连接云端模型服务，也可以在条件适合时使用本地模型。例如 Ollama 同时提供本地与云端调用入口。“不接云端模型 API”和“程序内部完全不用接口”是两回事。[Ollama 接口说明](https://docs.ollama.com/api/introduction)

第一次并不需要做一个全天候助手。可以先限制资料范围和问题，只完成一次有来源可查的研究任务，再看是否需要增加工具、接消息平台或长期运行。

### 也可以交付助手会用到的一部分能力

| 可以尝试的成果 | 具体可以做什么 | 在哪里、怎样使用 | 需要的工具或连接 |
| --- | --- | --- | --- |
| Skill 能力包 | 保存某类任务的方法、脚本、参考和模板 | 装入兼容 Agent 宿主，由宿主按规则使用 | 兼容宿主；脚本的依赖与接口另外注明 |
| MCP 工具服务 | 把查库存、读资料或处理文件提供给 AI 宿主调用 | 本地进程或远程服务，连接后由宿主使用 | MCP 实现与兼容宿主；底层业务连接按功能决定 |
| 模型适配成果 | 围绕特定数据训练模型或适配器 | 在匹配的推理环境加载，或调用托管版本 | 训练/推理工具、算力、基础模型和评估；与提示词、资料检索分开 |

Skill 可以是一套整理好的操作方法和配套文件，需要宿主来使用它；MCP 服务则可以把某个具体工具接给兼容应用。它们都能成为交付物，也都需要说明怎样安装、连接和使用，不能只给一个名称。[Agent Skills 格式](https://agentskills.io/home)、[MCP 架构](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture)

## 六、从表里选一个真的想试的东西

浏览这些表格时，可以留意自己在哪一行停了下来。

也许是一个自己的小程序，也许是能修改尺寸的模型，也许是一套把新数据变成图表的生成器。开始时不必先弄懂所有专业名词，先说清想做出的东西，以及拿到后希望怎样使用它。

例如：

> 想试做一个桌面收纳架模型，上层放笔，下层有两个小抽屉。希望能换角度观察，后面还能改尺寸。请先研究适合的制作和查看方式，做一个简单版本，并说明会交付哪些文件、怎样打开、需要哪些软件或接口。

也可以是：

> 想做一个自己手机上用的出行清单，能添加物品、勾选和保存。先研究合适的载体，推荐一种做最小版本。请把工程文件、实际使用入口和启动方法交代清楚。

专业方法可以让 AI 先调查，再一起判断。第一次只需要有一个足够具体的对象，能打开、能操作，或者能换一份输入再运行。

按用途保留必要的源文件和说明：想继续改设计，就要可编辑工程；想下次重新生成，就要程序和模板；想交接一个服务，就要知道它运行在哪里、怎样启动和查看状态。说明书、来源记录、测试与代码差异，也可以是交付的一部分。

然后实际用一次。转动那个模型，换一份名单，保存一张清单，或者把一个问题交给助手。新的想法，往往会从这次操作里继续长出来。
