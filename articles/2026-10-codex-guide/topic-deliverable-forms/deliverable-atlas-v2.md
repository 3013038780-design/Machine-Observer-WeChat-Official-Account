## 写作方向修正

邀请读者尝试以前没做过的成果。读者不局限于只会文字和图片的人：会做网站但没做过 App、小程序，会做平面图但没做过立体模型，也属于本文读者。不要求先证明旧方法不好，探索本身就可以成为起点。

“换形式能改善什么”保留为具体案例的说明维度，不再充当全文唯一命题。原标题《你要的也许不是一张图》偏窄，暂不推荐作为当前主标题。新标题候选：《除了熟悉的那些，你还试过让 AI 做什么？》。尚未确认。

## 怎样扩充而不继续混层

这是一份供写作选材的成果目录，不宣称数学意义上的互斥穷尽。按读者能辨认、能拿到或使用的成果设条目；每项设一个主要归属，组合与实现另记。网页、App、机器人可以共用同一个接口；不能因此把接口服务重复计成三项新能力。

分别记录五个维度：

1. 成果是什么：手机 App、三维模型、工作簿、查询服务。
2. 用来做什么：记账、预约、看空间、测算成本。
3. 怎样拿到和使用：浏览器打开、手机安装、平台内运行、导入软件、程序调用。
4. 制作与运行条件：软件、平台、依赖、账户、设备或服务。
5. 交付到哪一步：原型、源工程、可运行成品、已部署服务，以及对应验证。

源代码、压缩包、Git 仓库、说明与测试是交付组成或交接方式，不再与 App、三维模型等并列成独立成果家族。HTML、JSON 等是载体或技术，不直接当作成果名称。定时、事件触发是启动机制，不独立当作成果类型。

## 扩展调查目录

以下分组是编辑导航，非行业标准分类。每个示例是可继续调查的明确对象，不是已经制作或验证的能力承诺。为避免只按职业任务无穷增项，只在使用方式、编辑对象或实际交付内容有差别时继续拆分。

| 主要归属 | 具体可探索成果 | 使用与交付要点 |
| --- | --- | --- |
| 网站与浏览器应用 | 展示型网站；可搜索知识站；带登录与记录的业务应用；本地交互报告；可安装网页应用（PWA） | 区分静态展示、持续存储与本地使用；PWA 与网页应用存在包含关系，不重复计算为独立大类 |
| 手机和平板应用 | iOS App；Android App；平板绘画或记录工具；跨平台移动应用；手机小组件 | 目标平台、工程与安装体验分别说明；跨平台是实现路线，不等于另一种用户功能 |
| 平台内小程序与轻应用 | 微信预约小程序；支付宝服务小程序；抖音活动小程序；企业协作平台内轻应用；平台内嵌网页工具 | 分清小程序原生项目与内嵌网页；本轮未核查各平台现行接入规则 |
| 桌面与系统工具 | 桌面窗口应用；菜单栏或托盘工具；命令行工具；快捷指令；文件管理器扩展 | 写清用户从哪里启动、处理什么、结果保存在哪里；脚本语言另记 |
| 扩展与宿主软件插件 | 浏览器扩展；编辑器扩展；办公软件插件；设计软件插件；三维软件插件 | 交付适配指定宿主的软件包与源工程；不同插件不能仅交一段通用脚本 |

| 自动处理与系统连接 | 文件批处理程序；网页操作程序；数据同步程序；变更监测程序；按模板生成材料的程序 | 定时、手动、文件到达等是触发选项；交付程序与已配置运行流程分开 |
| 接口服务与可复用软件 | 数据查询服务；计算服务；文件处理服务；事件接收服务；客户端 SDK；本地软件库；可嵌入界面组件 | 前五类中 SDK 为调用端配套；接口按输入输出展开，下节详述 |
| 数据与可计算资料 | 清洗后的数据集；关系数据库；带公式工作簿；可重复分析的计算笔记本；可导入日历或书目记录 | 数据集、数据库、工作簿和分析过程分别说明，不按 CSV/JSON 后缀重复拆类 |
| 文档与出版成果 | 可修订正式文档；固定版式报告；电子书；可填写表单；可编辑演示稿；可打印桌游或教具 | 同一内容可有多个版本；按真实使用需求组合，不默认生成全部格式 |

| 三维与空间 | 可旋转产品展示；可编辑三维场景；参数化模型；角色绑定与动画；沉浸式空间体验 | 展示入口、几何模型与源工程不是同一文件；Blender 记在制作工具栏 |
| 工程与制造 | 二维尺寸图；参数化零件工程；装配工程；三维打印模型；激光切割图；电路原理图与 PCB 工程 | 可视预览、可编辑设计与制造准备分别确认，不能由文件后缀推定可直接生产 |
| 地理与科学计算 | 交互点位地图；可编辑地理数据；路线分析工程；数学推导与计算笔记本；可复现仿真工程 | 地图展示不等于完整 GIS 工程；计算结果与模型假设、运行程序共同记录 |
| 嵌入式与实体机器人软件 | 单片机固件；传感器采集程序；设备通信驱动；机器人消息节点；仿真场景与控制程序；运动规划或控制模块 | 指定板卡、传感器、机器人平台、协议与仿真/实机验证状态；软件成果不等于交付整台硬件 |
| AI 专用工作成果 | 可复用技能；接入工具的服务；针对任务的助手配置与程序；检索知识库及更新程序；评估数据与运行工具 | 技能、工具、知识资料和可运行助手分别记；“代理”不是省略实现和连接条件的万能名词 |

这份目录仍需针对各家族补充一手案例。不能将表中的全部项目写成 Codex 当前会话均能直接完成；应逐项确认制作路径。覆盖检查的重点是是否漏掉新的使用入口、操作对象与工程成果，不是继续增加计数。

## “机器人”展开到什么程度

| 具体成果 | 输入与动作 | 实际交付 |
| --- | --- | --- |
| 消息查询机器人 | 用户在指定聊天平台输入订单号，程序查数据库并回复状态 | 消息接收和回复程序、查询逻辑、配置示例、运行说明与验证记录 |
| 文件整理机器人 | 收到附件，识别约定字段、检查并保存，再回复处理结果 | 附件处理程序、消息连接代码、存储约定、异常处理与样例 |
| 网页操作程序（有时称 RPA 机器人） | 读取任务清单，在指定网站完成操作并记录结果 | 浏览器自动化工程、参数和选择规则、运行日志；不等同于消息机器人 |
| 机器人传感器节点 | 接收真实或模拟传感器数据，转换后发布给其他节点 | 指定框架的软件包、节点代码、消息定义与启动配置；需要对应环境验证 |
| 机器人运动模块 | 接收目标位置和当前状态，计算轨迹或输出控制指令 | 规划/控制代码、模型参数、仿真与测试材料；不能把未验证脚本写成已完成实机控制 |

第一、二项可以用 Python、JavaScript 等实现，但语言不是交付类型。第三项不一定使用 AI。后两项属于实体设备软件，不与聊天机器人混称。ROS 2 的发布/订阅官方教程只证实消息节点这一具体构成，不足以证明导航、抓取或整机控制已实现。

## API 不能只剩下三个字母

先解释一种具体可交付成果：让别的程序按约定提交数据，取得处理结果的服务。API 是广义的软件接口；本文举的是网络接口服务，不能把所有 API 都等同于网页地址。

| 可交付服务 | 传入什么 | 返回或完成什么 | 谁来调用 |
| --- | --- | --- | --- |
| 运费计算服务 | 重量、目的地、运输方式 | 运费明细与规则版本 | 网站、小程序、业务系统 |
| 库存查询服务 | 商品编号、仓库 | 可用数量、更新时间或明确的未找到状态 | App、订单系统、查询机器人 |
| 文件转换服务 | 文件、目标格式及选项 | 转换结果文件或任务编号 | 批处理程序、上传页面 |
| 预约登记服务 | 时段、登记字段 | 成功记录或冲突原因 | 小程序、前台网页 |
| 文本分类服务 | 待处理文字、类别规则 | 类别与约定字段，必要时说明无法分类 | 工单系统、资料整理工具 |
| 事件接收服务 | 外部系统推送的新订单等事件 | 接收确认，并按规则登记或启动后续任务 | 配置了事件推送的外部系统 |

以上是设计示例，未实际制作。事件接收服务中的 webhook 是按事件推送到接收端的连接方式，不宜与所有 API 划为互斥类别。

完整交付要分清三种状态：接口设计文档；可运行服务工程；已经部署并验证可调用的服务。按需要附接口说明、请求与返回样例、配置说明、错误处理与测试；涉及权限时交付权限机制及配置方法，不将真实凭证写入归档。SDK 是方便调用该服务的一套代码，不是服务本身。

## 下一阶段如何形成文章

读者起点：无论已经熟悉哪种成果，都可能还没想过其他制作入口。

核心判断：AI 协作值得探索的范围，不止熟悉工具中的下一份作品，也包括过去没有制作过的成果。

候选递进：从“会做网站，也未必做过 App 或小程序”建立入口；用少量跨领域首次尝试呈现具体成果；提供扩展目录供读者找到想试的对象；最后说明如何从一个可运行、可操作或可编辑的小版本开始。目录负责广度，案例负责让人看见成果，正文不逐条讲授全部技术。详细大纲需在研究后提交审核。
