# 正文表格精简试改：三列＋交办示例

日期：2026-10-23。状态：具体样例与编辑建议；尚未将全文 119 项全部转换。article-v2.md 与 V3 详细清单保持原样。

## 调整依据

用户认可完整稿，并指出五列过多，希望缩减，同时让读者知道怎样向模型提出要做这件成果。主线与 V3 分组、具体成果保留；调整的是每一行承担的阅读任务。

建议正文三列：**具体交付物｜能做什么、在哪里用｜可以这样跟 AI 说**。

- 第一列保留清楚的成果名称，方便读者辨认与继续了解。
- 第二列将具体作用、载体和使用动作合成一个短画面。
- 第三列给一句可据此交办的自然话，包含任务、成果形态及关键用法。避免只写“做一个 Agent”或“交付 API”。

工具/API 不再独立占一列；典型制作路径、平台/模型连接等进入相邻讲解。决定成果能否使用的关键条件仍就近说清，不将原五列全文塞入第三列。

## 可用于正文的样例

| 具体交付物 | 能做什么、在哪里用 | 可以这样跟 AI 说 |
| --- | --- | --- |
| iPhone App | 手机上的出行清单，添加、勾选后保留记录 | 做一个 iPhone 出行清单 App，能添加、勾选和保存物品，先做可测试版本。 |
| 微信小程序 | 微信里选择预约时段、提交并查看记录 | 做一个微信预约小程序，用户能选时段并提交，管理员能查看预约记录。 |
| 浏览器扩展 | 阅读网页时，点按钮保存摘录和网址 | 做一个浏览器摘录扩展，保存选中文字、原网址和备注，并能导出。 |
| 可旋转三维展示 | 浏览器里转动查看收纳架，源工程留作后续修改 | 做一个桌面收纳架的可旋转展示，在浏览器里看，并保留以后改尺寸需要的源工程。 |
| 本地文件生成器 | 选择名单，按模板生成一批证书 | 做一个本地证书生成器，读取名单按模板生成 PDF，换名单后还能再次运行。 |
| 资料研究 Agent | 本机反复接收研究任务，检索、补查并整理来源 | 做一个可反复接任务的本地研究助手，能根据查到的内容继续补查，并输出附来源的报告。 |
| 附件处理机器人 | 聊天里发来表格，收到处理结果 | 做一个聊天机器人，收到订单表后检查重复，返回结果文件。先推荐合适的平台。 |
| 运费计算 API | 网页、App 等提交参数，取得计算明细 | 做一个运费计算 API，输入重量和目的地，返回明细，附调用示例和启动方法。 |

以上是交办入口，不是保证一次提示即可完成的技术规格。沿用文章中“请 AI 先调查和推荐路径”的协作方法，后续按任务补齐条件、迭代和验证。

## 表外集中解释

表前只需交代一次：可以照第三列开始说，再补自己的材料、目标平台和使用习惯。工具、格式与接口由 AI 先调查推荐，并说明实际交付、打开方式与必要连接。

可给一条统一补充话：

> 先研究适合的实现方法，做一个简单可用版本。说明会交付什么、怎样打开或运行；需要的软件、账号、模型或接口先列清楚。需要我提供的资料或授权，也请明确指出。

这句话不在每行重复。用户仍决定任务目标与实际外部连接，示例不代表授权开通账号、付费或发布。

Agent/机器人组保留必要讲解：研究 Agent 的任务推进与消息机器人入口可组合；云端/本地模型和消息平台接口承担不同职责。精简表格不删除这些边界。

工程/三维组保留“能转动与能改尺寸”的区别；自动化组保留“程序与已配置运行”的区别；API 组保留“说明、服务程序与运行实例”的区别。复杂条目可在表后单独给完整示范，不将所有步骤挤入表格。

## 全文转换原则

保持 18 组与具体条目，不借缩列重新归大类或删去陌生成果。每行一句具体交办示例，按成果定制；名称、载体与关键动作不能被泛化。V3 五列详细清单继续作为研究与查阅版，正文使用三列的读者版本。
