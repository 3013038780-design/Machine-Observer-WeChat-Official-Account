# 协作缺口的第二次复核：检查什么、为什么不清楚、怎样推进

日期：2026-10-07。状态：编辑探索，待用户审阅。不是完整分类，也不是正文。承接 unknowns-audit-v1.md 与 outline-v6.md。

## 一、七维度的价值与不足

七项可以帮助防遗漏，但不能称为七种同层级、互斥的未知。

- 现状与事实是所有判断的背景，不仅是与目标并列的一项。
- 目标、成果和标准互相影响，尚未想清时更难独立填写。
- 方法里同时包含路线选择、流程安排与具体操作，各层可分别未知。
- 条件与边界混合资源、依赖、限制、权限和决定权。
- 标准是判断依据，验证是获得证据的动作；原表将证据又放进现状，两处有交叉。
- 七项没有单独表达双方理解不一致、要求冲突、旧信息过时、知道却表达不出来等情况。

因此不继续追求“再改成几项就完备”。保留七项作为编辑检查清单，正文采用日常问题和案例说明；如果短表保留，明确其用途是防漏，并允许关联。

## 二、需要分开的三个问题

### 当前需要弄清什么

用读者能识别的问句组织：现在发生了什么；希望为谁改善什么；想要什么成果；有哪些做法；有什么条件和限制；怎样判断值得、合适和完成。

这些问句覆盖原七项，但不要求开始前逐一回答，也不再将标题设计为若干种未知。

### 这件事为什么还不清楚

同一内容可能处于不同情况：

| 情况 | 需要怎样处理 |
| --- | --- |
| 不懂相关概念和方法 | AI 解释、展示例子、推荐并说明依据 |
| 缺少真实资料 | 查看现有材料，调查或测量；双方都缺事实时不能猜成结论 |
| 心中有感觉，却说不出来 | 让样例、对照、操作过程帮助表达，用户纠正 AI 的理解 |
| 有一个想法，但尚未证实 | 写清假设和依据，选择合适的小验证 |
| 几个方案都可行，难以取舍 | 明确优先要求，比较收益、成本和适用条件 |
| 要求彼此冲突，或不同人意见不一 | 先呈现冲突及后果，让有决定权的人选择 |
| 人与 AI 理解不同，或新旧决定冲突 | 复述当前理解、指出差异，确认有效决定 |
| 原先有依据，环境变化后可能失效 | 重查受影响的事实和方法，不无差别从头研究 |
| 已清楚且可执行，仍希望更好 | 比较优化方向与现有基线，尊重不能改变的要求 |

这不是新增九类正文。它解释原框架为什么不能仅靠“已知、未知”决定协作动作。

### 此刻需要 AI 帮到什么程度

帮助理解、提出选项、形成计划、执行、诊断、检查、整理交接，可以按当前任务组合。它们不是人的永久类型，也不是固定先后阶段。

还需要分清：人知道但 AI 未收到的内容，要提供材料或表达；AI 可帮助解释的知识，要说明并核查适用性；双方都缺的事实，要调查或试验；价值偏好和重要取舍，由人结合建议决定。AI 自信地知道不等于已获得可靠依据。

## 三、从检查清单走向行动判断

列出缺口之后，必须补上：当前最影响哪一个决定或动作；如果先不处理，会有什么影响；怎样取得足够依据；哪些工作可以同时继续。

优先级不能只按“未知最多的部分”决定。优先处理会改变方向、阻挡下一步，或导致大量返工的疑问；可在实际使用中再调整的细节可以暂定。具体选择结合成本与可逆性，不制造固定评分公式。

例子：旅游网站字体尚未选定，可以先做预算规则；是否需要多人同时编辑会影响方案，值得早些弄清。想试验行程安排是否省事时，可以先用样例或表格，不必先决定全部技术。

## 四、三个容易混淆的判断

- 能做出来：技术或操作可行。
- 符合约定：实现和产物满足当前要求。
- 值得做、实际有用：成果帮助目标对象解决问题。

三者需要相应证据，不能用页面能打开证明解决了旅行准备困难，也不能用用户喜欢外观证明预算计算正确。

补充来源：[NASA 系统设计过程](https://www.nasa.gov/reference/4-0-system-design-processes/)。已读过程关联、期望、需求、方案及持续迭代部分。其工程背景只帮助编辑区分需求、解法与检验，不要求用户采用航天工程流程，也不作为本篇新增重点方法。

## 五、长期协作的情境，不限于最初入口

微软研究的 [Human-AI Interaction Guidelines](https://www.microsoft.com/en-us/research/blog/guidelines-for-human-ai-interaction-design/) 将交互建议覆盖初次使用、使用中、出错时和长期使用。文章发表于 2019-02-01，针对 AI 产品交互设计，不能称为当前 Codex 工作流。已读完整指南正文；借鉴其覆盖全过程的视角，而非照抄四组阶段。

第二篇应覆盖开始、推进、判断和接续。未知会在实际成果出现后变化，原先清楚的目标也可能需要更新；工作流需提供重新进入的位置。

## 六、对文章的修正建议

保留 v6 的四部分：识别协作困难 → 方法介绍与总结 → 工作流提炼 → 情境示范。

第一部分：七项退为辅助检查，增加“缺什么”和“为什么缺”的区别，用两三个例子说明，避免叠加多张分类表。

第三部分：每轮选择需要取得的进展或证据，不只补知识；允许明确部分继续执行，也保留优化、诊断和恢复。重要选择由人参与，技术与专业流程由 AI 提出、解释和验证。

第四部分：标题改为“工作卡在不同地方，怎样说、怎样继续”。通过形成方向、推进工作、判断与接续三组编排示例，覆盖表详见 collaboration-situations-v1.md。分组只是阅读组织，不是三种起点或固定阶段。

不能宣称本次完成穷尽分类。目标是让读者能识别常见困难，并让 AI 协助诊断未预先列出的情况。
