# 协作情境覆盖表：从任何卡住的位置接入

日期：2026-10-07。用途：第二篇案例与提示词编辑素材，不是十四类必须记忆的分类。每行可以与其他行同时发生；未穷尽全部情况。

| 读者当前的情况 | 可怎样提出请求 | AI 应帮助取得的进展 |
| --- | --- | --- |
| 刚进入新领域，不知会面对什么 | 先解释这类工作的主要问题、常见做法和判断标准，结合我的条件推荐如何开始 | 初步认识领域，有依据的探索路线；不把完整课程当作开工前提 |
| 感到某件事不顺，但问题没定位 | 看现有材料和操作过程，找主要困难及可能原因 | 具体问题、依据和待验证原因 |
| 有参考效果，不会说明需求 | 帮我拆解参考中的布局、功能和使用过程，区分能观察到的部分与需要补问的部分 | 把感觉变成可讨论要求；图片无法证明的行为单独标注 |
| 手上有材料，但还不知可以做什么 | 先分析这些资料能支持哪些工作，指出缺口，并推荐值得尝试的方向 | 材料与用途的匹配，不先默认成果形式 |
| 目标和效果清楚，但方法未知 | 比较合适路线，解释取舍，推荐本轮做法和检查方式 | 可执行的阶段方案及推荐依据 |
| 知道怎么做，但不想亲自操作 | 按既定要求推进，说明当前能执行到哪里并检查结果 | 范围内执行及真实结果；不会因用户已有方法而重复教学 |
| 有多个可行方案，难选 | 按我的优先要求比较，指出需要验证或由我决定的取舍 | 能理解的差异、推荐及尚未证实的判断 |
| 有理想成果，但时间或资源不够 | 保留核心目标，比较本轮范围和做法如何调整，说明影响 | 可行范围和代价；不擅自删除固定要求 |
| 工作做到一半，失败或停滞 | 先看报错、日志或操作过程，定位阻碍，说明下一步需要什么 | 可验证原因、恢复办法或具体依赖；不盲目重写全部 |
| 有成果，但不会判断好坏 | 解释这类成果的评价标准，并区分已检查和还需试用的部分 | 可理解标准和相应检查证据 |
| 不满意，却说不清哪里不对 | 结合参考、实际操作和我的感受，诊断目标、结构、方法还是细节出了问题 | 合适层级的修改建议，必要时展示对照帮助表达 |
| 结果符合原需求，但实际不解决问题 | 检查原先对问题和使用情境的判断，提出调整目标或方案的建议 | 找到需求与实际价值之间的差距；不只继续修细节 |
| 已有完整方案，希望更好 | 区分固定要求和可讨论做法，比较流程、工具及验证的优化收益 | 有基线的改进建议，允许保留原方案 |
| 中断后继续，或多人/多轮决定冲突 | 整理当前成果、有效决定、冲突和未完成项，给出可继续的下一步 | 恢复一致理解和状态；整理记录不能替代实际访问权限 |

## 正文取舍

集中用少量典型片段展开，其余情境用短提示或对照补足。避免十四个小节、十四条模板或旅游场景反复套用。参考效果、表达不满意可用内容或设计场景，材料用途可用研究或运营场景。

同一网站任务可表现从需求形成、路线选择到试用后问题重定义的变化；这是展示理解变化的案例，不是所有工作的必经路径。

每个示例同时写清：当下困难 → 对 AI 的请求 → 应得到什么 → 根据结果怎样继续。示例不承诺一次回答解决全部问题。
