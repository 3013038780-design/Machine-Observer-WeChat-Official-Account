## 文章目标

回答：目标、成果、标准或方法尚未想清楚时，怎样与 AI 一起形成工作方法、推进任务并判断结果；已经有方案时，怎样评估更好的做法。

受众：缺少专业经验、需要处理长期复杂工作的人。旅游日程网站为主要例子，内容、研究、运营场景用于说明迁移。

## 导语

- 日常协作困难：不知道该做什么；知道想要的效果但不会做；已经开始却卡住；结果不满意但说不清；已有方案仍想改进。
- 用户不必先独自完成需求和工作流，AI 可参与解释领域、发现遗漏、比较方法及验证。
- 引出已有方法与实践。导语之后直接进入方法介绍。

## 一、已有方法怎样组织工作

### 1. 双钻模型：形成问题与选择解法

- 重要问题：过早确定网站、App 等成果形式，可能还没弄清真正困难。
- 过程：发现现状 → 定义问题 → 发展多种方案 → 小规模测试与改进。
- 核心解释：两轮探索和收敛；需求可在过程中形成；测试也能促使重新定义问题。
- 例子：旅行准备困难可能来自资料分散、预算漏项或同行协调，先分析过程，再比较表格、网站或已有工具。
- 分工：人提供真实体验，AI 整理资料、补充知识和提出方向，真实使用者反馈参与验证。
- 所得结果：问题理解、候选解法与选择依据。
- [Design Council 原始说明](https://www.designcouncil.org.uk/resources/the-double-diamond/)

### 2. Claude Code 官方实践：从理解项目到验证改动

- 重要问题：目标明确，仍可能改错位置、漏掉规则或没有验证。
- 过程：探索 → 规划 → 实现并验证 → 提交可审查版本。
- 核心解释：先看真实项目；计划写清行为和检查；工具反馈支持修正；小而明确的改动可直接执行。
- 例子：预算功能先了解已有数据，再明确计算与保存规则，实际运行检查后保存版本。
- 分工：人确认用途与关键规则，AI 提出方法、实施并展示检查证据。
- 所得结果：可执行计划、实际产物与检查结果。
- [官方最佳实践](https://code.claude.com/docs/en/best-practices)

### 3. Anthropic 工程方法：固定流程与动态推进

- 重要问题：哪些步骤能提前确定，哪些需要根据新结果调整。
- 核心解释：稳定重复任务使用预设过程；未知路径使用行动、观察、决策循环；两者可组合。
- 例子：固定周报取数和核对流程，对照网站故障的逐步诊断。
- 必要条件：实际工具反馈、当前状态、范围与停止条件；解释执行框架如何组织运行。
- 分工：AI 在范围内调整动作，人参与方向和重要取舍。
- 所得结果：有依据的下一步及可持续推进的过程。
- [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

### 4. OpenAI 工作流实践：长期任务的状态与复盘

- 重要问题：新旧决定混乱、计划与完成混淆、继续时重复劳动。
- 过程：目标 → 阶段计划 → 当前任务 → 执行证据 → 复盘改进。
- 核心解释：目标、方法、进度与证据各有用途；用实际结果诊断流程问题；文件结构是示例约定。
- 例子：网站保存反复返工，判断是需求没说明、计划漏检查，还是检查证据没有留下。
- 分工：AI 整理状态和建议改进，人确认关键改变。
- 所得结果：能接续的当前记录及有依据的流程改进。
- [OpenAI 指定实践文章](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex)

### 5. Superpowers：方法怎样保存为技能

- 重要问题：有效做法如何重复采用，避免每次重新交代。
- 过程：理解意图 → 比较方案 → 设计 → 实施计划 → 执行、检查与审查。
- 核心解释：设计回答做什么和为什么；计划明确怎么实施和检查；任务规模对应不同流程深度。
- 例子：可行性试探、已有项目小改动和新建完整网站，需要不同产物与过程。
- 分工：技能提供可复用指导，AI 执行，人审阅重要决定；工具、权限和实际验证仍必需。
- 所得结果：可以复用的步骤、任务与检查规则。
- [作者仓库](https://github.com/obra/superpowers)

### 本节总结

- 比较五项的侧重点与取得的结果，不排优劣、不称统一标准。
- 补入人机协作研究：明确分工和持续共创均存在；AI 可补充视角，但协作效果要验证。
- 方法、产品实践、工程架构、社区技能的层次区别清楚。
- 引出：选择具体流程前，需要判断当前缺什么。

## 二、怎样判断当前缺口

- 七项作为防漏清单：现状与事实、目标与对象、成果与需求、标准与取舍、方法与流程、条件与边界、验证与证据。
- 每项可同时有已知、假设和未知；不要求开工前全部填写，不称完整互斥分类。
- 区分缺口原因：不懂知识、缺事实、表达困难、方案难选、要求冲突、理解不一致、旧信息失效。
- 区分信息在谁那里：用户掌握的经历和偏好、AI 可以解释的知识、双方需要调查验证的事实。
- 下一步优先处理会改变方向、阻挡执行或造成大量返工的问题。

## 三、从这些方法提炼协作工作流

用流程图说明，并标明这是编辑归纳。

了解当前状态 → 判断信息是否够做下一步 → 必要时补缺口 → 明确本轮任务 → 执行并检查 → 更新状态，结束或进入下一轮。

- 补缺口：解释、调查、比较、样例、试验，按问题选择。
- 本轮任务：成果、材料、固定要求、检查标准与决定权。
- 检查：区分技术可行、符合约定和实际有用，各用相应证据。
- 回退：目标/需求有问题则重新理解；方法/范围有问题则调整计划；实现错误则修正执行。
- 接续：保存有效决定、实际成果、检查证据、未解决项与下一步。
- 允许跳过已明确环节，允许已有方案优化，不要求全部问题一次消除。

## 四、不同困难下，怎样提出请求、怎样继续

精选情境展开，其余用短对照补充；情境可以组合，不作为固定人群分类。

- 陌生领域或方向未定：了解领域、分析问题、提出候选方向及一次尝试。
- 只有材料或参考效果：分析材料用途、拆解效果、通过样例形成要求。
- 目标清楚但方法未知：比较路线、推荐本轮成果、明确实现与检查。
- 方法清楚希望委托：给规则与材料，范围内执行并检查。
- 多方案难选或资源不足：说明取舍、比较可行范围与代价。
- 执行失败或结果不满意：提供实际过程，诊断合适层级的修改。
- 不会评价或需求失效：补标准、取得证据，必要时重新定义问题。
- 已有方案求优化：尊重固定要求，以当前方案为基线比较收益。
- 中断或决定冲突：恢复状态、整理有效决定并接续。

每个展开例子写清：当前困难 → 怎样向 AI 表达 → 应得到什么 → 根据结果怎样继续。

## 结尾

- 用户可以从不完整理解开始，AI 参与形成认识、方法和成果。
- 通过实际证据逐步更新判断；流程匹配领域与当前条件。
- 稳定有效的方法再考虑保存复用，衔接下一篇的项目资料、规则文件和技能。
